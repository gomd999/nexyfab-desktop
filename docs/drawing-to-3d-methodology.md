# 도면 기반 3D 생성 방법론 (Drawing-to-3D Methodology)

> 2026-07-11 확정. 텍스트/이미지/실도면 입력에서 **검증된 복합 3D(STEP)** 를 뽑는 NexyFab 파이프라인 방법론.
> 근거 논의: 위시빌더 200L 수처리 탱크(회전체 용기), AK엔지니어링 ULD 파레트 랙(철골 프레임) 실사례 + NexyFab shape-generator 기존 자산 대조.

---

## 0. 한 줄 요약

**"치수 박힌 2D 도면"을 공통 중간표현으로 삼고, 거기서 결정론적으로 3D를 빌드한 뒤, 3D를 도면으로 역투영해 원본과 대조하는 루프로 정확도를 보증한다. 커널은 intent 레벨에서만 혼합한다(기하 핸드오프 금지).**

---

## 1. 문제 정의와 핵심 통찰

### 1.1 왜 텍스트→3D 직행은 실패하는가
- 텍스트→3D는 **부족 결정(under-determined)** 문제 — 해가 무한대. 모델이 애매함을 안은 채 형상을 one-shot으로 뱉으면 non-manifold·치수 오류가 구조적으로 발생.
- 손코딩 OpenSCAD도 같은 함정: 장식용 파라미터(형상에 미반영), 가짜 assert, 눈대중 간섭 확인. 검증 없는 생성은 입력이 뭐든 신뢰 불가.

### 1.2 왜 도면 경유가 정확도를 올리는가 (수학적 근거)
- 엔지니어링 **정투상 도면(정면·평면·측면)은 정의상 3D를 유일하게 복원 가능**하도록 만든 표현. 도면→3D는 원리적으로 well-posed 문제.
- 도면은 **입력이자 동시에 정답지**: 생성한 3D를 다시 도면으로 역투영(HLR)해 원본과 겹치면 오류가 치수 diff로 객관적으로 드러난다. one-shot에는 이 정답지가 없다.

### 1.3 "바로 생성" 금지 — 계획-실행 분리
```
이미지+도면(또는 텍스트)
  → [추출/계획] 뷰·치수·토폴로지 → 구조화된 중간표현   ← LLM/비전은 여기까지만
  → [실행] 결정론적 SCAD/B-rep 빌드                    ← 여기부터는 코드가 정확히
  → [검증] 역투영 도면 diff + manifold + 간섭
  → [교정] 자동 루프 (기존 scadCorrectionLoop 재사용)
```
LLM은 **계획(중간표현)까지만** 만들고, 기하는 항상 결정론 코드가 방출한다.

## 2. 파이프라인 — 입구 둘, 백엔드 하나

```
                    ┌── [입구 A] 실제 DWG/DXF + 사진   → 도면 = 오라클(진실, 바로 검증)
텍스트/도면/이미지 ──┤
                    └── [입구 B] 일반 텍스트           → 도면 = 계획서(사람 승인 체크포인트)
                                     ↓ (공통)
                     치수 박힌 2D 도면 스펙 = 커널-무관 intent 그래프
                                     ↓ 결정론적 방출
                     OpenSCAD ─or─ OCCT(B-rep) ─or─ Manifold   ← 형상클래스 라우팅
                                     ↓
                     역투영→도면 diff + manifold + 어셈블리 간섭검사
                                     ↓ 실패 시 교정루프
                                검증된 STEP / STL
```

### 2.1 입구 B의 체크포인트가 최대 장점
텍스트에서 생성한 도면은 **모델의 가설**이다(오라클 아님). 따라서 3D로 가기 전에 **치수 박힌 2D 스케치를 사람이 승인/수정**한다. SCAD 디버깅보다 도면에서 숫자 하나 고치는 게 100배 쉽다 — **3D를 만들기 전에 틀린 걸 잡는 것**이 정확도의 엔진.

### 2.2 복잡도 자동 분기
- 단순 형상(구멍 뚫린 블록 등) → 기존 텍스트→SCAD 직행 유지 (도면 경유 강제 안 함).
- 복합 형상 / 사용자가 신뢰·수정을 원할 때 → 도면 체크포인트 경유.

## 3. 역할 분리 — 도면 vs 이미지

| 입력 | 역할 | 금지사항 |
|---|---|---|
| **도면(DXF/치수 스케치)** | **치수의 유일한 진실.** 모든 수치는 여기서만 | — |
| **이미지(사진·AI 렌더)** | 토폴로지/형태 힌트("원뿔 맞나", "리브 4개") + vision 비평 | **치수 결정 금지** (AI 이미지는 치수가 부정확 — 예쁜 렌더에 속아 치수 틀린 3D가 나옴) |

## 4. 복합 형상 = one-shot이 아니라 분해

```
도면/이미지 → 컴포넌트 분할 (용기/내부/노즐, 또는 기둥/보/거셋)
  → 각 부품 개별 복원 + 개별 도면대조 검증
  → 어셈블리 결합 + 간섭검사 (기존 assemblyInterference 재사용)
```
- 부품마다 도면과 대조돼 통과하면 합쳐도 신뢰 가능. 나눠서 각각 검증 > 한 방.
- "복합"의 90%는 거대 boolean이 아니라 **부품 조립**이다.

### 4.1 제품군별 생성기 (같은 인프라, 다른 파라다임)
| | 회전체 용기 (수처리 탱크) | 철골 프레임 (파레트 랙) |
|---|---|---|
| 모델링 | revolve(벽 단면) + extrude(배플) + 노즐홀 | 단면(ㄷ형강 등)을 **부재 중심선 그래프 따라 스윕** + 조인트/거셋/베이스플레이트 |
| 데이터 | 지름·높이·원뿔각·배플수 | 노드+부재 그래프 + 단면 배정 |
| 공유 | 단면 라이브러리 · 어셈블리 · 간섭검사 · 검증루프 (전부 공통) | |

## 5. 커널 전략 — 커널-무관 intent + 라우팅

### 5.1 OpenSCAD의 진짜 천장 (파이프라인으로 못 고침)
OpenSCAD = CSG/메시(CGAL) 커널. 다음 3개는 커널 자체 한계:
1. **진짜 필렛/블렌드** — 필렛 엔진 없음 (minkowski는 전체 엣지 뭉갬 + O(n²) + 가변반경 불가 = 가짜)
2. **거대한 불리언 트리** — CGAL이 복잡 입력에서 느리고 취약
3. **자유곡면/유기형상** — `$fn` 다각형 근사, 이중곡률 로프트 표현 불가

### 5.2 대응 = intent를 커널-무관으로 짜고 형상클래스별 라우팅
| intent 프리미티브 | 라우팅 | 근거 |
|---|---|---|
| 각진/회전체/프레임/단순 boolean | **OpenSCAD** (드래프트) | 빠르고 충분 |
| `fillet/chamfer(edgeSelector, r)` | **OCCT** BRepFilletAPI (replicad) | 진짜 롤링볼 필렛. EdgeFinder 브리지 기존재 |
| 무거운/깨지기 쉬운 boolean | **OCCT** BOPAlgo 또는 **Manifold** | B-rep exact 연산 / 신형 로버스트 메시 boolean |
| `loft/sweep(sections[], rails[])` | **OCCT** ThruSections/BSpline | 덕트·전이부·유선형 — 단면+가이드레일로 명세 |

- **엣지 선택은 좌표가 아니라 기하 조건으로** ("수직 엣지 전부", "면 A∩면 B") — EdgeFinder 패턴.
- 자유곡면도 **단면 스테이션 도면**으로 명세 → 도면 체크포인트가 그대로 적용 (선박 로프팅과 동일 사상).
- OCCT 필렛 실패(엣지 몰림 등)도 검증루프가 잡아 반경↓/부분집합 재시도 or 사람 플래그.

### 5.3 정직한 경계선
**예술적 SubD 스컬프팅**(곡선으로 명세 불가한 순수 조형)은 어떤 텍스트→CAD 파이프라인으로도 안 됨. 산업 제조엔 거의 불필요 — 이 선은 넘지 않는다. (블레이드·선체류의 in/out-scope 세부 기준은 §12.6)

## 6. 커널 혼합 규칙 (핵심)

> **부품의 최종 기하는 커널 하나가 책임진다(kernel-of-record). 혼합은 ① 부품 사이 ② 드래프트↔기록 단계 사이 ③ 교차검증에서만. 기하를 커널 간에 넘기지 않는다 — intent를 다시 방출한다.**

### 6.1 왜 기하 핸드오프는 금지인가
- OpenSCAD 출력 = 메시. **해석적 면/엣지 정보가 이미 소실** → 여기에 진짜 필렛 불가(테셀레이션 엣지에 필렛 = 각진 띠).
- 메시→B-rep 역변환은 연구급 난제 + 손실 큼. B-rep→메시 방향도 정밀도 강등 편도 티켓.

### 6.2 올바른 혼합 3패턴
1. **부품 단위 라우팅** — 부품 하나 = 커널 하나. 어셈블리에서 공존(간섭검사는 메시로 가능).
2. **★ 드래프트/기록 분리** (추천):
   ```
   intent (단일 소스)
     ├─ [드래프트] JSCAD/OpenSCAD → 초고속 프리뷰·vision 비평·도면 체크포인트 (필렛 생략/근사)
     └─ [기록]    OCCT → 같은 intent 재생 + 필렛/로프트 → 검증 → STEP
   ```
   사용자 반복 루프는 드래프트(초 단위)에서, 승인 후 기록 커널이 1회 정밀 빌드. 기하 핸드오프 없음 = 손실 제로.
3. **듀얼-방출 교차검증** — 같은 intent를 두 커널이 독립 빌드 → 부피·질량속성·단면적 대조(N-version). 방출기 버그 검출. massProps 비교기는 FEA 스위트 재사용.

### 6.3 예외
3D프린팅/시각화가 최종 목적이면 메시끼리 Manifold boolean 혼합 무방(출력이 어차피 메시). STEP·기계가공 목적일 때만 엄격 적용.

## 7. 검증 그물 3겹

| 그물 | 잡는 오류 | 구현 |
|---|---|---|
| 도면 체크포인트 (사람/규칙) | **의도 오류** — 모델이 텍스트를 잘못 이해 | 입구 B 필수, 입구 A는 자동 |
| 3D→역투영→도면 diff | **방출 오류** — 빌드가 의도에서 벗어남 | HLR 투영(기존) + **치수 diff 채점기(신규)** = 교정루프의 loss 함수 |
| 이미지 vision 비평 | **토폴로지 블런더** | scad-vision-critique 재사용 |
| (+) manifold/watertight | 렌더 전 기하 결함 | FEA 스위트 재사용 |
| (+) 어셈블리 간섭검사 | 부품 충돌 (임펠라↔배플 등) | assemblyInterference 재사용 |

## 9. DWG 자동화의 정직한 단계 (과장 금지)

완전 자동 DWG→3D는 연구급 난제 (다중 뷰·치수·용접기호의 모호성).
- **Phase 1 (즉시):** 도면 = 레퍼런스, 핵심 치수를 템플릿/intent에 입력 → 파라메트릭 생성. AI 이미지 페이크를 진짜 STEP으로 대체.
- **Phase 2 (보조):** DWG→DXF 변환 후 치수·프로파일 **자동 추출을 "씨앗"으로** 제공(사람 검증 전제). "완전 자동"이라 주장하지 않음.

## 10. 구현 로드맵

1. **커널-무관 intent 스키마 확정** ← 모든 논의의 수렴점, 최우선
   - 프리미티브: §12.1 4+1 체계 (Sketch+Extrude/Revolve, Skeleton+Sweep/Loft, Non-Local(Fillet/Shell/Draft), AssemblyGraph, SheetMetal)
   - 엣지셀렉터: §12.2 [생성이력+기하조건] 스키마 + 재해석 실패 플래그
   - 라우팅 규칙 명시 (§5.2 표) + PMI/카탈로그 필드 (§12.5)
2. **파일럿 = 200L 수처리 탱크** (가장 깨끗한 revolve 케이스)
   - ① 스케치 스텁 실체화 + ② 단면 라이브러리 최소셋(탱크벽/원뿔/배플/노즐)
   - ③ 도면 diff 채점기 v1 (주요 치수 비교부터)
3. **입구 B (텍스트→도면 체크포인트→3D)** 파일럿 배선
4. **ULD 랙으로 프레임 생성기 확장** (중심선 그래프 + 단면 배정)
5. **입구 A (DXF 씨앗 추출)** — Phase 2

## 12. 범용 CAD 확장 기준 (General-Purpose CAD Extensions)

> 2026-07-11 추가. 본 파이프라인을 특정 수처리 탱크/프레임 도메인을 넘어 보편적 기계 부품·구조물 설계로 확장할 때의 기준. 외부 리뷰(4대 프리미티브·Persistent Naming·뷰 라우팅 제안)를 검증해 과장 3곳 보정 + 누락 3개 보충 후 채택한 것.

### 12.1 4+1대 범용 프리미티브 체계 및 커널 라우팅
대부분의 산업용 CAD 기하는 다음 5가지 의도(intent)의 조합으로 수렴되며, 형상 클래스별로 드래프트(OpenSCAD/JSCAD)와 기록(OCCT/B-rep) 커널로 자동 분기된다. (§5.2 라우팅 표의 일반화)

| # | 범용 Intent | 의미 | 드래프트 커널 | 기록 커널 |
|---|---|---|---|---|
| 1 | **Sketch + Extrude / Revolve** | 단면 기반 두께 부여·회전체 (축, 실린더, 플랜지, 하우징 바디) | `linear_extrude`, `rotate_extrude` | `MakePrism`, `MakeRevol` |
| 2 | **Skeleton + Sweep / Loft** | 경로 따라 단면 변형 (배관, 크랭크축, 덕트, 이형 전이부) | 다각형 근사 스윕 — 무겁고 취약, 프리뷰 한정 | `MakePipeShell`, `ThruSections` (exact 곡면) |
| 3 | **Non-Local Feature (Fillet/Chamfer/Shell/Draft)** | 가공성·쉘화. **주조·사출 대응 위해 구배(Draft)·쉘(Shell)을 필수 포함** | 생략 또는 근사 | `BRepFilletAPI`, `MakeShell` |
| 4 | **Assembly Topology Graph (Boolean/Joint)** | 부품 체결·간섭 제어 | `union`/`difference` | `BOPAlgo` (exact 면 분할) |
| 5 | **★ Sheet Metal (판금)** | 절곡(bend)·전개(unfold) — 위 4개에 안 맞는 독립 클래스 | — | 기존 `sheetmetal-flat/step` 경로 자산 재사용 |

### 12.2 시맨틱 셀렉터와 Persistent Naming의 한계
엣지/페이스 지정은 좌표·인덱스가 아닌 **[생성 이력(source feature) + 기하 조건 필터]** 조합 스키마를 강제하여, 파라메트릭 수정 시 참조가 깨지는 현상(Persistent Naming Problem)을 **완화**한다.

```json
{
  "feature": "Fillet",
  "selector": {
    "source_feature": "Main_Housing_Cut",
    "filter": "IntersectingEdges",
    "condition": { "direction_vector": [0, 0, 1], "min_length": 10.0 }
  },
  "radius": 3.0
}
```

이렇게 짜야 드래프트 커널은 필렛을 통째로 생략해도 오류가 없고, 기록 커널은 정확한 엣지를 찾아 STEP을 방출한다.

**정직한 한계 명시:** 이 스키마도 완벽한 해결이 아니다 — 예컨대 새 피처 컷이 기존 시맨틱 엣지를 둘로 쪼개면(split edge) 셀렉터가 모호성에 빠진다. **셀렉터 재해석 실패 시 시스템은 임의의 기하를 뱉지 않고 즉시 검증 루프 플래그를 발생시켜 사람 개입을 요청한다.**

### 12.3 형상 클래스별 도면 뷰 라우팅 (입구 B 체크포인트 UI 표준)
텍스트에서 도면 가설을 생성할 때, 사람이 승인할 도면 레이아웃은 부품 토폴로지에 따라 결정론적으로 라우팅된다. LLM은 입력 분석 즉시 형상 클래스를 판정하고, 해당 레이아웃 가설을 UI로 먼저 승인받는다.

| 형상 클래스 | 승인용 도면 레이아웃 |
|---|---|
| 회전체/대칭형 (용기, 축, 기어) | **반단면 1뷰** (Half-Section) — 1뷰로 3D 복원 유일성 확보 |
| 프레임/구조물 (랙, 트러스, 배관망) | **3D 중심선 노드 그래프**(skeleton) + 단면 스펙 명세 |
| 각주형/Prismatic (기계 부품, 하우징) | **표준 3각법 3뷰** (+필요시 상세도/단면도) |
| 판금형 (브래킷, 인클로저) | **2D 전개도**(flat pattern) + 절곡선/각도 표 |

### 12.4 기대-ΔV 구간 기반 교차 검증 (고정 임계치 금지)
기록 커널(B-rep)과 드래프트 커널(메시) 부피 대조 시 고정 % 임계치를 쓰지 않는다.
- **메커니즘**: 드래프트에서 생략된 정밀 피처(필렛 등)로부터 **기대 부피 차이 구간을 역산** (≈ Σ 필렛 단면적 × 대상 엣지 길이). 기록 커널 방출 부피가 이 구간을 이탈하면 boolean 오류 또는 셀렉터 오탐으로 간주해 플래그.
- **보완 관계**: 부피 대조는 오류를 **탐지**하지만 **위치를 못 짚는다** — 위치 특정은 스테이션별 단면적 대조(§7 역투영 도면 diff)가 담당. 둘은 상호 보완재.

### 12.5 Intent 1급 데이터: 표준부품 카탈로그와 공차(GD&T)
1. **표준부품 카탈로그 참조**: 볼트·나사산·베어링·기어는 기하를 생성하지 않는다 — **규격 카탈로그 DB를 참조해 블록 배치** (STEP에서 나사산은 관례상 cosmetic). 범용 CAD의 상당 부분은 "만들기"가 아니라 "규격 불러와 배치"다.
2. **GD&T / PMI 통합**: 도면 체크포인트는 명목 치수 외에 **공차 주석을 함께 나른다.** NexyFab C2 GD&T 정책에 따라 intent 스키마에 PMI 필드를 1급 데이터로 통합.

### 12.6 보정된 정직한 경계선
- **과장 금지 상한선**: 도면이 존재해도 나사산 결합부 디테일, 용접 기호 해석, 누적 공차 분석에는 기하학적 모호성이 남는다. 본 기준의 상한은 "완벽한 자동화"가 아니라 **"체계적으로 기하를 자동화하고 오류를 기계적으로 탐지·격리할 수 있는 정밀도"** 다.
- **자유곡면 스코프 기준** (§5.3 보정): 터빈 블레이드·프로펠러·선체는 무조건 제외가 아니다 — **스테이션별 단면 좌표 + 트위스트 룰이 명세로 존재하면 in-scope** (loft로 빌드 가능). 단면 명세 없이 CFD 최적화 결과물로만 존재하는 순수 자유 조형 곡면만 out-of-scope.

### 12.7 실전 방어 규칙 (Runtime Defense Rules)

> 2026-07-11 추가. §12 초안에 대한 2차 외부 리뷰(셀렉터 무한플래그·ΔV 오탐·카탈로그 간섭 오탐)의 리스크 진단 3건을 채택하되, 제안 해법을 각각 한 단계 강화해 확정한 규칙.

#### 12.7.1 셀렉터 실패의 3단 완충지대 (§12.2 보강)
셀렉터 재해석 실패(split edge 등) 시 즉시 사람을 부르지 않는다 — 단, 자동 복구를 조용히 삼키지도 않는다:

```
1차: 이력 전파 (exact)     — OCCT 연산의 Modified/Generated 이력 맵에서 원본 엣지의
                            후손 엣지들을 결정론적으로 추적. 추측이 아니라 기록.
2차: 기하 휴리스틱 (fallback) — 이력이 끊긴 경우에만 방향/길이 정합 매칭
3차: 도면 diff 채점 통과 시 수용 — 단 "셀렉터 자동 재해석됨" provenance 마크를 결과물에
                            남겨 최종 승인 화면에서 사람이 확인. 채점 실패 시에만 즉시 플래그
```

- 임의 고정 임계치(예: "80% 정합") 금지 — 1차는 이력 기반이라 exact, 2차 휴리스틱의 수용 여부는 임계치가 아니라 **3차 diff 채점이 결정**한다.
- 원칙 유지: 자동 복구가 실패하면 임의의 기하를 뱉지 않고 플래그. "임의 기하 금지"(§12.2)와 "자동화 유지"를 양립시키는 구조.

#### 12.7.2 피처별 기대-ΔV 추정기 (§12.4 보강 — 포기 금지)
단순 필렛 공식(단면적×엣지길이)은 Shell/Draft에 무효하나, ΔV 검증 자체를 버리지 않는다 — **피처별 1차 추정기 + 허용 밴드 폭 차등**으로 분기:

| 생략 피처 | 기대-ΔV 1차 추정 | 밴드 폭 |
|---|---|---|
| Fillet/Chamfer | Σ 단면적 × 엣지 길이 | 좁게 |
| **Shell** | ≈ 표면적 × 쉘 두께 | 넓게 |
| **Draft(구배)** | ≈ Σ(대상 면적 × tan(구배각) × 높이/2) | 넓게 |
| 추정 불가 피처 | ΔV 검증 스킵 → 단면 diff 가중 상향 | — |

- prismatic(sketch-extrude 계열) 부품은 드래프트 커널에서도 **2D `offset()` 후 extrude**로 shell을 근사 가능(OpenSCAD offset은 2D 전용이나 단면에는 적용 가능) → 해당 클래스는 ΔV 대조가 다시 유효.
- 부피 대조(전역 탐지)와 스테이션별 단면 diff(위치 특정)는 §12.4대로 상호 보완재 — 가중치는 피처 구성에 따라 동적으로.

#### 12.7.3 조인트 스펙 검증 — 간섭 "제외" 금지 (§12.5 보강)
카탈로그 부품(나사산 외경 볼트)과 체결 홀(내경)은 정의상 겹치므로 일반 간섭검사는 100% 오탐하고, 교정루프가 홀을 넓히려는 버그 루프에 빠질 수 있다. 그러나 해법은 **간섭 연산 제외(exemption)가 아니다** — 제외하면 볼트가 반만 걸렸는지/엉뚱한 홀에 박혔는지도 못 잡는 검증 구멍이 생긴다.

> **기대-접촉 검증(spec-validated contact):** 어셈블리 그래프의 조인트 선언(볼트↔홀 = threaded joint)이 **허용 관통 밴드**를 갖고, 간섭검사기는 실제 관통량이 그 밴드 안에 있는지 검증한다. 너무 얕음 = "체결 안 됨" 플래그, 너무 깊음/위치 이탈 = "잘못 박힘" 플래그. 조인트로 선언되지 않은 접촉은 기존대로 간섭.

- 일반화: 억지끼움(press fit)·용접·개스킷 등 "의도된 간섭" 전반에 같은 원리 적용 — 조인트 타입별 허용 밴드를 카탈로그/스키마에 정의.
- 결과: 오탐 제거 + 검증력 강화(단순 제외 대비), §12.5 조인트 인터록 사상과 합치.

### 13.1 "복합 3D 가능한가"에 대한 공식 입장
아키텍처상 Yes — 복합을 "스켈레톤/조인트 기반 결정론적 조립" 문제로 치환했고(§4), 부품별 diff 채점 통과분만 어셈블리에 합류시켜 오류 전파를 끊는다. **단, 검증된 것은 규칙의 논리적 정합성이지 작동하는 컴파일러가 아니다.** §8의 미구현 5조각이 "가능하다"와 "된다" 사이의 거리이며, 진짜 리스크는 규칙이 아니라 구현 그라인드(OCCT 엣지케이스, diff 채점기 캘리브레이션)에 있다. → 파일럿이 답한다.
