## 2. ★ 새로 찾은 실제 결함 2건 — 둘 다 「입력을 준 사용자」만 만난다

### ⚠ 결함 A — 벽식 횡력 검토의 **풍 경로가 한 번도 작동한 적이 없다**

```
wind.V0 만 주면 → ok:false
attempted: ["풍: Cannot read properties of undefined (reading 'at')"]
```

`shear-wall-check.mjs` 의 풍 분기가 `lateral.map((x) => Number(x.p.at?.tx ?? 0))` 로
읽는데, `lateral` 의 원소는 **연직 병합된 스택**이라 `.p`(부품)가 없다. **항상 throw** 한다.
즉 지진(`seismic.R`)이 있어야만 검토가 돌고, `wind.V0` 는 **아무 효과가 없다.**

그런데 거부 문구는 이렇게 말한다:

> 층전단력이 없으면 분담을 계산할 수 없습니다 — **R 또는 V0 중 하나만 주면 검토가 돕니다.**

**사실이 아니다.** V0 만 준 사용자는 문구를 믿고 값을 줬는데 영원히 판정을 못 받는다.
260729d 에 캐노피에서 잡은 것과 **같은 형태의 재발**이다(문구는 V0 를 받는다는데 받을
경로가 없음). 다만 이번은 더 나쁘다 — 그때는 검토 자체가 없었고, 이번은 **있다고 말한다.**

고치는 것 자체는 작다. 스택에 `cx`/`cy` 가 있고 어셈블리 AABB 도 있으므로 B·D 는 거기서
낸다. **다만 「무엇을 B·D 로 볼 것인가」를 정해야 한다**(벽 중심 범위는 과소, 건물 외곽이
맞다) — 정하지 않고 아무 값이나 넣으면 그게 지어내기다.

### ⚠ 결함 B — `seismic.importance` 어휘가 지진·풍에서 다르고, 거부 문구가 거짓말한다

```
seismic:{R:5, importance:'1'} → 지진: input gate failed: importance: must be one of special, grade1, grade2
```

MCP 스키마는 `seismic:{R, zone, siteClass, importance}` 를 문서화했다. 그런데
**지진 계산기는 `special|grade1|grade2`**, **풍 계산기는 `'1'` 계열**을 받는다.
사용자가 자연스러운 `'1'`(또는 풍 쪽 어휘)을 주면 지진 산출이 통째로 실패한다.

더 문제는 그다음이다. 실패하면 헤드라인이 **이미 준 R·V0 를 또 달라고 한다**:
> 필요 입력: 반응수정계수 R (1~8) · 기본풍속 V0 (m/s)

사유는 `attempted` 안에만 묻혀 있다. **「입력이 없다」와 「입력이 있는데 값이 허용범위
밖이다」는 다른 말**이고, 후자를 전자로 말하면 사용자는 고칠 방법을 알 수 없다.
이 세션 내내 지킨 구별(해당 없음 ≠ 판정 불가 ≠ 이상 없음)의 **네 번째 갈래**다.

## 6. 측정 방법 — 이번에 바꾼 것과 다음에 바꿀 것

이번에 바꾼 것: **params 를 변수로 놓고 쟀다.** 그동안 세 번(260729c·d·260730·260731)을
전부 1조합으로 재서, 「입력을 준 사용자가 보는 문서」는 한 번도 측정하지 않았다.
결함 A 는 **제품에 계속 있었고 측정 방법 때문에 안 보였던 것**이다.

다음에 바꿀 것: **거부 문구가 사실인지 검사한다.** 「V0 를 주면 돕니다」가 참인지는
V0 를 주고 돌려 보면 알 수 있다. 문구와 동작의 일치는 지금 아무도 검사하지 않는다 —
이 세션에서 잡은 결함 중 최소 3건(캐노피 V0 · 풍 경로 · importance)이 그 형태였다.
