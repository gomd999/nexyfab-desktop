# NexyFab AI 3D·정밀 CAD 구현 현황 및 검토 보고서

- 기준일: 2026-08-09 (Asia/Seoul)
- 대상: NexyFab AI 3D 생성 → 정확도 검증 → 전문가 정밀 CAD 편집 흐름
- 작업 원칙: `점검 → 구현 → 검증·조정 → 다음 단계`
- 보호 원칙: 기존 Closed Beta 계정·비밀번호·저작물 및 참고 코퍼스를 수정하거나 훼손하지 않음
- 현재 판정: **내부 구현 및 검증 완료 / 실제 외부 생산 증거 대기**

## 1. 요약 평가

현재 NexyFab에는 AI로 생성한 6축 로봇을 편집 가능한 구조로 만들고, 정밀 CAD 검증과 전문가 검토를 거쳐 별도 개정본으로 통합할 수 있는 기술적 흐름이 구현되어 있다.

AI 결과를 곧바로 생산 가능 CAD로 주장하지 않으며, 다음 경계를 명확히 유지한다.

1. AI가 편집 가능한 3D 구조를 생성한다.
2. 기구학·충돌·간섭·케이블·구동계 요구사항을 검증한다.
3. 카탈로그 부품을 증거 기반으로 선별한다.
4. 전문가가 정밀 CAD 통합 대상을 오프라인으로 검토하고 이중 서명한다.
5. 승인된 경우에도 원본을 덮어쓰지 않고 content-addressed `r+1` 개정 ZIP만 생성한다.
6. 개정본을 다시 정밀 검증한다.
7. 네이티브 CAD·제조 검증·최종 전문가 서명이 모두 있어야 릴리스 적격성을 판단한다.
8. 적격 판정과 실제 릴리스 실행은 분리한다.

따라서 현재 구조는 **AI 초안 생성 후 정확도를 높이고, 필요할 때 전문가가 정밀 CAD 단계로 진입하는 구조**라는 목표에 부합한다. 다만 실제 복잡 제품의 생산 적합성을 최종 입증하려면 외부 네이티브 CAD 환경과 제조 전문가의 실제 증거가 추가로 필요하다.

- Ed25519 서명으로 정확한 통합 대상 해시를 검증
- 승인 이전에는 CAD 수정, 저장, 견적, 주문, RFQ 또는 릴리스 부작용 없음
- 승인된 대상은 원본을 덮어쓰지 않고 새로운 `r+1` 개정본으로 생성
- 모터·감속기·베어링 18개 occurrence와 관련 메이트·구조 참조를 모두 교체
- 결과물은 content-addressed ZIP으로만 반환하고 작업공간에 자동 영속화하지 않음

### 2.5 통합 후 증거와 릴리스 경계

- `r+1` 프로그램, 매니페스트, 적용 영수증 및 정밀 검증 보고서를 다시 결속
- 18개 occurrence, 156/156 운동 프레임, 충돌 0, 정밀 간섭 0을 확인
- 외부 네이티브 CAD 증거와 제조 검증을 별도 서명 증거로 요구
- 최종 도메인 검토자와 독립 검토자의 이중 서명 요구
- 최종 검토 결과가 적격이어도 실제 릴리스 실행·게시·원본 변경은 수행하지 않음

## 7. 현재 상태 평가

### 7.1 잘 구현된 부분

1. **AI와 정밀 CAD의 역할 분리가 명확하다.**  
   AI가 시작점을 빠르게 제공하고, 정밀도와 생산 책임은 검증·전문가 승인 단계가 담당한다.

2. **검증 실패를 숨기지 않는다.**  
   초기 모델의 22개 간섭과 외부 증거 부족을 그대로 차단 사유로 유지한다.

3. **원본과 개정본의 경계가 안전하다.**  
   승인 후에도 원본을 덮어쓰지 않고 새로운 해시 기반 개정본을 만든다.

4. **증거 추적성이 높다.**  
   프로그램·카탈로그·하우징·검증·검토·적용 결과가 해시로 결속된다.

5. **전문가 검토가 형식적 버튼 승인이 아니다.**  
   역할 분리, 신뢰 키, 대상 해시 및 전자서명을 검증한다.

6. **Closed Beta 자산 보호 기준을 유지했다.**  
   계정·비밀번호 해시·저작물에 변화가 없음을 스냅샷으로 입증했다.

### 7.2 아직 생산 완료로 볼 수 없는 부분

현재 내부 소프트웨어 구조는 충분히 정리됐지만, 실제 복잡 제품을 생산 가능한 CAD로 확정했다는 뜻은 아니다.

| 외부 검증 항목 | 현재 상태 |
|---|---:|
| 네이티브 CAD 워커 구성 | 0/7 |
| 네이티브 워커 상태검사 통과 | 0/7 |
| 네이티브 canary 통과 | 0/7 |
| 네이티브 작업 승인 | 0/108 |
| 서명된 제조 검증 | 없음 |
| 최종 독립 이중 서명 | 없음 |

따라서 현재 정확한 표현은 다음과 같다.

> AI 3D에서 전문가 정밀 CAD로 이어지는 안전한 제품 구조와 검증 체계는 구현되었다. 그러나 실제 네이티브 CAD 및 제조 전문가의 외부 증거가 없어 생산 릴리스 완료 상태는 아니다.

### 7.3 보안 및 운영 리뷰

- 릴리스 관련 API는 fail-closed 방식으로 설계되어 증거가 없거나 불일치하면 진행하지 않는다.
- 서명 검증 키는 환경 등록을 요구하며 개인키는 서버나 패킷에 포함하지 않는다.
- 자동 저장과 자동 릴리스를 분리해 오조작 범위를 줄였다.
- 프로덕션 빌드에서 `REDIS_URL` 미설정 경고가 확인되었다. 현재 인메모리 rate limit은 다중 서버 배포에서 공유되지 않으므로, 실제 운영 배포 전 Redis/Upstash 등 중앙 rate-limit 저장소 설정이 필요하다.
- 최종 릴리스 실행 기능은 의도적으로 구현하지 않았다. 실제 릴리스가 필요할 때에는 별도의 권한·감사·롤백 정책을 정의한 뒤 추가해야 한다.

## 8. 다음 진행 순서

외부 환경이 준비되면 다음 순서로 같은 작업 사이클을 재개한다.

1. **점검**
   - SOLIDWORKS, Inventor, CATIA, Creo, Parasolid, DWG, Revit 워커 명령과 라이선스 확인
   - 워커 identity와 버전 고정

2. **진행**
   - 7개 워커 health probe 실행
   - 워커별 deterministic canary 실행
   - 108개 네이티브 작업 수행

3. **검증·조정**
   - 네이티브 파일 열기, 어셈블리 트리, 관절 의미, 단위, 토폴로지 및 STEP round-trip 검증
   - 실패 항목만 수정하고 새로운 증거 개정본 생성

4. **제조 검증**
   - DFM, 공차 누적, BOM, 체결부, 케이블, 재료 및 공정 계획 검토
   - 정확한 18개 구동계 occurrence 대상에 제조 전문가 서명

5. **최종 검토**
   - 도메인 전문가와 독립 검토자의 서로 다른 키로 최종 이중 서명
   - 완료 감사 스크립트 재실행

6. **별도 승인 후 릴리스**
   - 릴리스 적격성과 실제 실행을 다시 분리
   - 배포 전 백업, 롤백, 감사 로그 및 중앙 rate limit 확인
