> **질문**: SolidWorks/Autodesk 를 대체할 수 있는가?
> **답**: 오늘은 **판금 단품 제작자**에게만 가능. 나머지는 아래 게이트를 통과해야 한다.
> **근거**: 이 문서의 모든 판정은 **코드 실행 실측**이다(추정 아님). 측정 산출물:
> `scripts/spike/topo-naming-k22.result.json` · 커버리지 실측은 §2.

## 0. 결론 3줄

1. **파라메트릭 재생성이 끊겨 있다.** 상류 치수를 바꿔도 하류 피처가 안 따라온다(실행 증명).
   이것 없이는 기능 수와 무관하게 CAD 시스템이 아니다.
2. 그러나 **원인이 좁고 명확하다** — 연구가 아니라 **데이터 모델 리팩터 + 불리언 명명 교체**다.
3. 위상 명명은 **순수 extrude 경로에서 이미 완전**(생존 100%·오매칭 0%). 붕괴는 **불리언 한 곳**이다.

## 1. 실측 ①: 하류 재생성 (블로커 #1)

```
extrude(depth=10) → fillet,  상류 depth 10→25 편집
downstreamOf(f1) = ['f2']    ← 의존성 그래프 정확
f1 changed? true             ← 상류 변경됨
f2 (fillet) changed? false   ← 하류 미갱신  ★
```

**원인**: `src/lib/cad/filletProfile.ts:95` — `FilletFeature.childExtrude: ExtrudeFeature` 가
상류 노드 **참조가 아니라 복사본**이다. `featureTreeEdit.ts:305-310` 의 증분 재방출(`mustEmit` =
변경분 + 하류)은 **정확히 구현돼 있으나**, 재방출된 fillet 이 자기 안의 낡은 복사본을 다시 쓴다.

**진단**: 의존성 그래프·증분 재방출 기계는 이미 맞다. 고칠 것은 **payload 가 상류를 참조하게 하는 것**
(`childExtrude: 객체` → `childId: string`, 방출 시점 트리 해석). 12종 `FeatureKind` 전부 + 저장된
트리 마이그레이션 + 테스트가 따라오므로 **몇 주 규모**(며칠 아님, 다년 아님).

## 2. 실측 ②: 위상 명명 K2.2 스파이크 (ADR-017)

OCCT 실 커널로 전 시나리오 측정. 하네스 신뢰도는 실 브릿지와 대조해 **36/36 일치** 확인.
A = 생성이력 명명(`topoNaming`+`composedTopo`) · B = 기하 시그니처(`edgeCorrespondence`)

| 시나리오 | A 생존 | **A 오매칭** | B 생존 | **B 오매칭** | n |
|---|---|---|---|---|---|
| S1 extrude→치수변경 | **100%** | **0%** | 99.6% | 0.4% | 504 |
| S2 불리언컷→치수변경 | 90.7% | **7.6%** | 91.3% | 8.7% | 912 |
| **S2b 2번째 컷 삽입** | 0% | **50%** ★ | 89.9% | 10.1% | 288 |
| S3 필렛참조→치수변경 | **100%** | **0%** | 97.7% | 2.3% | 264 |
| S4 EditOp 중간삽입 | 0% | **0%**(전부 명시 상실) | 100% | 0% | 144 |

**ADR-017 필수 기준(S1~S4 오매칭 0%) → 불합격.** 단 파괴 지점이 특정됐다:

**근본 원인 2개**
1. `composedTopo.ts` 의 `seam.{k}` 가 **중점 정렬 순서**에 붙은 위치 이름 — 순서가 뒤바뀌면 같은
   이름이 다른 엣지를 **조용히** 가리킨다.
2. **역할 접두사(`a/`,`b/`)가 위치 기반** — 툴을 하나 더 삽입하면 기존 `b/e.vert.0` 이 **새 툴**의
   엣지를 가리킨다. **S2b 의 오매칭 50% 가 이것.** 사용자가 1번 구멍에 건 필렛이 2번 구멍으로 옮겨간다.

**붕괴 조건**: 배율이 아니라 **불리언 피처 간 상대거리가 좁아질 때**(축소 ×0.2~0.3 에서 A 14~17%,
모서리 밀착 구멍은 ×0.75 에서도 33%). 순수 extrude 는 ×0.2~×5 전 구간 무결.

**커버리지 0(단, 전부 조용히 틀리지 않고 명시 거부)**: revolve 명명 · pattern · 필렛 결과 위 재참조.

## 4. 로드맵 — 비용 오름차순, 의존 순서

### R0 — 즉효 (수일)
- **R0-1 역할 접두사 위치→피처ID** (`a/`,`b/` → 노드 id). 커널 불필요. **S2b 오매칭 50% → 명시 상실로 강등.**
  스파이크가 지목한 "가장 비용 대비 효과 큰 한 방".
- **R0-2 B 매처에 신뢰도 하한 + 2위 마진 게이트** — 애매하면 −1 반환(조용한 추측 금지).
  B 는 상실을 절대 보고하지 않아 실패가 전부 오매칭이 된다 — D1 관점에서 A 보다 위험.
- **R0-3 스케치 캔버스 원 방출** — 솔버 절반 활성화(B등급 1번).

### R1 — 하류 재생성 (수 주) ★대체의 관문
`childExtrude` 등 embedded payload → `childId` 참조. 12종 피처 + 영속 마이그레이션 + 회귀.
**이게 되기 전엔 "파라메트릭 CAD"라고 부를 수 없다.**

### R2 — 불리언 위상 명명 커널 이력 전환 (수 주)
`composedTopo.ts` 의 위치 기반 seam 명명을 `BRepAlgoAPI_BooleanOperation` 의
`Modified()/Generated()/IsDeleted()` 상속으로 교체. **`topoNaming.ts`(extrude)는 손대지 말 것 —
100%/0% 로 이미 완전하다.** ADR-017 대안 (a)를 **불리언에 국한** 적용.

### R3 — 실측 치수 (수 주)
OCCT 로 참조 엔티티 실측 → 도면 치수. 도면이 제조로 나가는 관문. R2 위에 얹힌다(참조 안정성 필요).

### R4 — 배선 일괄 (수일~2주)
B등급 2~6번. 신규 개발 없음, 순수 배선.

### R5 — 재지정 UX 1급 승격
S4 는 A 가 생존 0% 지만 **오매칭 0%·100% 명시 상실** — D1 방침이 의도대로 작동한 지점이다.
여기는 고칠 게 아니라 **"참조 상실 목록 + 원클릭 재지정"** 으로 받아낸다. 재지정 UX 품질 = 제품 품질.

### R6 — 커버리지 회수 (분기 단위)
revolve/pattern 명명 · 로프트(현재 프리셋 3종 보간)·스윕·나사산·면 드래프트 실형상 ·
end condition(관통/면까지/박판) · 피처 단위 패턴 · PDM(잠금·체크아웃·머지) · 익스포트 포맷 확대.

## 6. 정직한 재평가

- 이전 감사가 "피처 히스토리 구현됨"으로 보고했으나 **부정확했다.** 편집 연산(삽입·재정렬·suppress)은
  진짜지만 **재생성이 전파되지 않는다.** 코드 존재만으로 판정하고 실행하지 않은 결과다.
  → **교훈: 이 저장소의 원칙(생성≠검증)을 감사 자체에도 적용할 것. 실행하지 않은 판정은 판정이 아니다.**
- 반대로 코드베이스의 **자기 주석은 놀랄 만큼 정직하다** — `filletProfile.ts:66-75`, `topoNaming.ts:15-17`,
  `nonlinearAnalysis.ts:27`("full 3D nonlinear solver 를 싣지 않는다"), `xtImport.ts`("B-rep 미재구성"),
  SLDPRT 라우트("파서 날조 금지"). 문제는 코드가 거짓말한 게 아니라 **요약 문서(ADR-016·
  OWN_PRO_CAD.md)가 실상을 잘못 전달**한 것이다.
- 강점은 진짜다: 구속 솔버·판금 전개·STEP 인터롭·FEA 는 경쟁력이 있다.
  현재 상태는 **"CAD 시스템"이 아니라 "잘 만든 CAD 인접 도구 모음"** 이고, R1~R3 이 그 경계를 넘는다.
