## 0. 전제 — 왜 "복제"이고 밑바닥이 아닌가

기계 드라이버의 실제 구조는 **도메인 무관한 척추 + 도메인별 어휘·게이트**로 나뉜다:

```
NL 브리프 → [계획 IR] → 결정론 빌드 → [측정 게이트 체인] → 검증 패키지 → 사람 검토
             ▲도메인            ▲도메인                    (척추=재사용)
```

- **재사용(도메인 무관):** 거부 IR(패키지 미산출)·게이트 오케스트레이션·PDM 검토 루프·
  GA3 zero-touch 계측 배선·3면 표면(API/MCP/웹)·정직 불변식(생성≠검증·날조 금지).
- **교체(도메인별):** ① 계획 어휘(무엇을 짓나) ② 게이트의 측정(무엇이 맞는지 = 그
  도메인의 계산). 예: 기계=치수/부피, 토목=구조코드, 인테리어=피난코드.

**따라서 각 분야는 "새 CAD를 처음부터"가 아니라 "척추에 도메인 플러그인 하나 꽂기"**다.
기계에서 부품 8종을 87.5%까지 올린 그 패턴 그대로.

**불변 천장(정직):** 복제해도 각 도메인의 법적 상한은 그대로다. 토목·건설의 구조
날인은 4단계가 상한(면허 책임) — "코파일럿"이지 "대체"가 아니다. 조경·인테리어는
설계 자체의 법적 제약이 약해 5에 접근 가능(인허가 단계만 검토).

**그리고 zero-touch는 도메인마다 새로 n=0**이다. 어느 분야도 자기 파트너 실측
없이는 5단계를 선언할 수 없다(측정 없는 목표는 날조 — 불변).

## 1. Phase 0 (선행·비-코드) — 기계 4→5 증명

**네 분야 확장의 전제.** 기계에서 파트너 실측으로 zero-touch가 처음 숫자가 되는
순간, "이 틀이 복제할 가치가 있다"가 입증된다. 이게 없으면 미증명 틀을 네 번
복제하는 셈. → 파트너 트랙(사용자 결정) + `AI_DESIGN_PARTNER_ONBOARDING.md`.

> 이 Phase는 코딩이 아니라 결정·실사용. 아래 Phase 1~5와 **병렬**로 흐를 수 있다
> (파트너 시계는 주~월, 코드 시계는 세션).

## 2. Phase 1 (공유 인프라) — 도메인 드라이버 추상화

기계 전용 `design-driver`에서 **도메인 무관 척추를 추출**해 `DomainModule` 인터페이스로:

```
interface DomainModule {
  planner:  (brief) => DomainPlan            // 도메인 계획 어휘
  gates:    Gate[]                           // 도메인 측정 게이트
  packager: (plan, gateResults) => Package   // 도메인 산출물
  fixtures: Fixture[]                         // 결정론 인수 픽스처
}
```

- 재사용: `runDriver`(거부 IR·게이트 체인)·PDM·GA3 배선·3면 표면.
- 산출: 기계 = 첫 `DomainModule` 참조 구현(리팩터, 무회귀).
- **규모**: 중(추출·리팩터). ≈ 1~2 세션. **이후 각 도메인 = 이 인터페이스 구현.**

## 3. Phase 2~5 — 도메인별 트랙 (각 "1/0 → 3~4")

각 트랙 = `DomainModule` 구현 + 도메인 게이트 + 픽스처 + 3~5 인수 테스트.
기계 백로그(WB-*)와 동일한 리듬: 1 트랙 = 1 도메인 형상군.

### Phase 2 — 토목 (CD, Civil Driver) · 1 → 3~4
- **계획 어휘:** 구조 부재(보·기둥·기초·옹벽·트러스) — 하중·경간·재료·단면.
- **게이트(측정):** 코드 준수 계산 — **eng-knowledge 계산기 61종 + KDS/KBC/KCSC
  소비.** 실측: 응력·처짐·전도·활동 안전율 vs 허용. 결정론·법정 근거.
- **패키지:** 구조계산서 + 부재 도면 + 물량.
- **재사용 자산:** 계산기 61종·코퍼스 44·KCSC·교량/간이구조검토 코퍼스(이미 LIVE).
- **천장:** **4** (PE 날인 = 법적). 표면 라벨 "면허자 최종 검토 필수·대체 아님" 고정.
- **규모:** 중~대. **첫 마일스톤:** RC보 1종 fixture + 처짐/응력 코드 게이트 → 패키지.

### Phase 3 — 건설 (CN, Construction) · 1 → 2~3
- **성격이 다름:** 설계보다 **물량·공정·간섭**. 드라이버가 아니라 정량화 파이프라인.
- **계획 어휘:** 건축 요소 → 수량. **게이트(측정):** BOQ 정합(물량 = 도면 실측)·
  공정 선후행 타당성·BIM clash(간섭 게이트 재사용 가능).
- **천장:** 물량/공정 **5 근접**(날인 없음)·구조 부분 4.
- **규모:** 중. **첫 마일스톤:** 평면 → 물량표 게이트(수량 실측 대조).

### Phase 4 — 인테리어 (IN, Interior) · 0 → 3~4
- **계획 어휘:** 공간·벽·문·가구·조명 배치.
- **게이트(측정):** **건축 코드 준수** — 피난동선 거리·유효폭·수용인원·이격/클리어런스·
  조도. 전부 측정 가능·결정론.
- **천장:** **5 가능**(설계 자체는 날인 약함, 인허가 단계만 검토).
- **규모:** 대(전문가 자산 얕음 — 코드 테이블부터). **첫 마일스톤:** 평면 + 피난동선
  게이트(거리/유효폭 실측 vs 코드).

### Phase 5 — 조경 (LS, Landscape) · 0 → 3~4
- **계획 어휘:** 식재·구배·관수·하드스케이프.
- **게이트(측정):** 관수 커버리지(스프링클러 반경 vs 대상 면적)·구배(배수 기울기
  min/max)·식재 간격.
- **천장:** **5 가능**(법적 제약 약함).
- **규모:** 대(자산 가장 얕음). **첫 마일스톤:** 관수 배치 + 커버리지 게이트.

## 4. 순서 근거 (왜 이 배열인가)

1. **Phase 0(기계 증명)이 먼저** — 틀의 복제 가치를 입증. 비-코드·파트너 시계라
   Phase 1~과 병렬.
2. **Phase 1(추상화)** — 한 번 하면 네 도메인이 전부 이 위에 얹힘.
3. **토목 먼저(Phase 2)** — 천장은 4로 낮지만 **자산이 가장 풍부**(계산기·코드·코퍼스
   LIVE) → **가장 빨리 3~4 도달**하고, 결정론 코드 게이트로 **도메인 추상화를 실전
   검증**. 시장·보조가치도 큼.
4. **건설(Phase 3)** — 토목 인접(물량·구조 공유).
5. **인테리어·조경(Phase 4~5)** — 천장은 높으나(5 가능) 자산이 얇아 리프트가 큼 →
   추상화가 검증된 뒤에 이식하는 게 효율적.

> **정리:** 자산 풍부·즉효(토목/건설) → 천장 높음·리프트 큼(인테리어/조경) 순.

## 6. 정직 불변식 (전 도메인 공통)

1. **생성≠검증·날조 금지** — 게이트가 실행·측정한 것만 통과. 오입력 → 패키지 미산출.
2. **법적 천장 라벨 고정** — 토목·건설 구조는 "면허자 최종 검토·대체 아님"을 제품
   표면·문서에 고정. "대체" 언어 금지.
3. **zero-touch는 도메인마다 새로 측정** — 커버리지(축 A)로 "대체" 선언 금지. 각
   도메인 GA3 첫 실측 전까지 유보.
4. **매트릭스 정본화** — 각 도메인도 `*_COVERAGE_MATRIX.md`로 실행 근거 표를 둔다
   (기계 매트릭스와 동형). 의견이 아니라 표로 단계를 답한다.
