# ANSYS 조달 사양 대비 미충족 항목과 계획 (2026-08-01)

> 대조 대상: **ANSYS Mechanical Enterprise + Discovery Enterprise** 조달 사양서
> 대조 방법: 사양서 각 항목을 `src/app/[lang]/shape-generator/fea|analysis` · `src/lib/cad-ir` 코드에 직접 대조
> 관련 문서: [`ai-path-measurement-260731.md`](./ai-path-measurement-260731.md) · [`accuracy-roadmap.md`](./accuracy-roadmap.md)

---

## 0. 이 문서의 범위와 한계

- **이것은 제품 로드맵이 아니라 「특정 조달 사양서에 대한 격차 분석」**이다.
  사양서는 범용 상용 FEA 패키지 조달 기준이고, 우리 제품이 겨냥한 축과 다르다.
  **항목이 미충족이라고 곧 결함은 아니다** — §5 에서 「하지 않을 것」을 명시한다.
- 난이도는 **상대 규모**(S/M/L/XL)로 적는다. **사람-월 추정은 적지 않는다** —
  근거 없는 기간은 계획이 아니라 희망이다. 규모 판단의 **근거**만 적는다.
- 「됨/안 됨」 판정은 **코드 확인**에 근거한다. 실행해 보지 않은 항목은 그렇게 적는다.

## 1. 대조 결과 — 한 장

```
fea/ 모듈        176개 (테스트 175개)
 └ 실제 3D 격자 위에서 도는 것   11개   ← HEX8/TET10/femSolver/topology3D
 └ 나머지 165개                        ← 닫힌해 공학 계산기 (핸드북 계산)
```

**「176개 해석 기능」은 과고지다.** 사양서가 말하는 FEA 는 3D 격자 위의 유한요소해석이고,
그 기준으로 우리는 **11개 + gmsh 사면체 메셔**다.

| 구성 | 충족 | 부분 | 미충족 |
|---|---|---|---|
| ① 전처리 | 3 | 2 (P8·P9) | **7** (P1~P7) |
| ② 솔버 | 12 | 6 (S1·S2·S5~S8) | **11** (S3·S4·S9~S17) |
| ③ 후처리 | 5 | 0 | **3** (O1~O3) |
| Discovery | 0 | 0 | **4** (D1~D4) |
| 공통 | 0 | 1 (C2) | **1** (C1) · 1 해당없음(C3) |

> 집계는 §2 열거와 **한 건씩 대응**한다. 「부분(◐)」은 **충족이 아니다** — 값은 나오지만
> 사양이 요구하는 범위(3D·임의 형상)가 아니라는 뜻이고, 미충족 쪽에 가깝게 읽어야 한다.

## 2. 미충족 항목 전수

난이도 표기: **S**=옵션·배선 수준 · **M**=모듈 하나 · **L**=서브시스템 · **XL**=다년 과제

### 2.1 전처리 (Pre-Processor)

| # | 사양 항목 | 현재 | 왜 안 되나 | 난이도 |
|---|---|---|---|---|
| P1 | **Hexa dominant 격자** | ✗ | gmsh 를 `Algorithm3D=1`(Delaunay 사면체)로만 호출. gmsh 자체는 `RecombineAll`/`Recombine3DAll` 지원 | **S~M** |
| P2 | **Sweep 격자** | ✗ | gmsh `Extrude`/transfinite 로 가능하나 **BREP 이 있어야** 한다. 현재 STL 만 투입 | **M** |
| P3 | **Multi-zone 격자** | ✗ | 형상을 스윕 가능 영역으로 분할하는 로직이 필요 — gmsh 옵션으로 안 됨 | **L** |
| P4 | **Direct meshing (Body to Body)** | ✗ | 다물체 조립 격자·접촉면 자동 인식 파이프라인 부재 | **L** |
| P5 | **하이브리드 격자** | ✗ | P1+P3 의 조합 | **L** |
| P6 | **재료물성 엑셀·그래프·표 입력** | ✗ | 코드 내 재료 라이브러리(`library/materials.ts`)만. 파일 인입 경로 없음 | **S** |
| P7 | **표·함수 경계조건** | ✗ | `fea/boundaryConditions.ts` 는 **프리셋 라이브러리**. 시간·공간 함수 BC 없음 | **M** |
| P8 | **Material Designer(등가 재료물성)** | ◐ | 복합재 라미네이트 ABD(CLT)만. 일반 대표체적요소(RVE) 균질화 없음 | **L** |
| P9 | Defeaturing | ◐ | 메시 힐링·단순화는 있으나 **CAD 피처 제거(필렛·홀 억제)** 와 다름 | **M** |

> **P1~P5 의 공통 병목: gmsh 에 STL 만 넣고 있다.**
> Debian 의 gmsh 는 OpenCASCADE 를 링크한 빌드다(Dockerfile 주석 참조). 즉 **STEP 을 직접
> 먹일 수 있는데** 우리는 STL 로 삼각화한 뒤 넣는다. 그 결과:
> - 곡면이 이미 삼각형으로 근사돼 **원래 곡률 정보가 소실**된다
> - 스윕·transfinite 은 **면·볼륨 위상**이 필요한데 STL 에는 없다
>
> → **STEP 직접 투입이 P1·P2 를 동시에 여는 열쇠다.** 이것이 이 계획의 1순위인 이유.

## 4. 계획

### 4.0 선행 — **모든 격자 항목의 병목부터**

> **gmsh 입력을 STL → STEP 으로 바꾼다.**

현재: `형상 → STL 삼각화 → gmsh Merge → TET4 → TET10 승격`
목표: `형상 → STEP → gmsh(OCC) → 곡면 그대로 격자`

얻는 것:
- 곡률 정보 보존 → 필렛·보어 응력집중 정확도 향상 (현재 A5 plate-hole Kt 오차 ~5.6%)
- **면·볼륨 위상이 생겨 P2(Sweep)·P1(Recombine) 이 가능해진다**
- STL 삼각화 실패 경로 하나가 사라진다

⚠ **위험**: STEP 인입이 실패하는 형상이 있을 수 있다. **폴백을 지운다는 뜻이 아니다** —
STL 경로는 그대로 두고 STEP 을 우선 시도, 실패 시 강등한다(gmsh 어댑터의 기존
`null 반환 → 옥트리 폴백` 규약과 동일한 형태).
⚠ **검증 없이 전환하지 않는다**: 기존 A1~A5 검증 케이스가 STEP 경로에서 **같거나 나은**
값을 낼 때만 기본 경로로 승격한다.

### 4.1 1단계 — 값이 큰 것부터 (A군 + 모달 기반 B군)

| 순 | 항목 | 왜 이 순서인가 |
|---|---|---|
| 1 | **4.0 STEP 직접 투입** | 뒤의 격자 항목 전부가 여기에 걸려 있다 |
| 2 | **P1 Hexa dominant** | 4.0 직후 옵션 추가로 열린다 |
| 3 | **S5 3D 조화가진** | `modalFEM` 위에 복소 응답 — 기반 있음 |
| 4 | **S6 모드중첩 랜덤진동** | 같은 기반. SDOF → 3D 로 승격 |
| 5 | **O3 엑셀 추출 · P6 재료 파일 인입** | 사용자가 즉시 체감, 비용 최소 |

### 4.2 2단계 — 실무 요구가 확인되면

P2(Sweep) · P7(함수 BC) · S4(상변화) · S8(일반 post-buckling) · O1(애니메이션) · O2(결과 비교)

> ⚠ **2단계는 착수 조건이 있다: 실제 사용자가 그 항목 때문에 막혔다는 근거.**
> 사양서에 적혀 있다는 것만으로는 착수하지 않는다 — 조달 사양서는 특정 제품의 기능
> 목록이지 우리 사용자의 요구가 아니다.

### 4.3 3단계 — 큰 것 (개별 판단)

S9(J-적분·SIF) · S12(DOE/응답면) · S1(3D 음향-구조) · S7(3D 로터다이나믹스) · P8(RVE 균질화)

각각 **독립적으로 사업 근거가 서야** 착수한다. 묶어서 「FEA 강화」로 하지 않는다.

## 5. 하지 않기로 하는 것과 그 이유

**이 절이 이 문서에서 가장 중요하다.** 못 하는 것을 나열만 하고 전부 하겠다고 적는 계획서는
계획이 아니다.

| 항목 | 하지 않는 이유 |
|---|---|
| **S13 APDL · S17** | 스크립트 언어를 새로 만드는 일. 우리의 대안은 **자연어 → 결정론 파이프라인**이고, 그게 우리 차별점이다. APDL 을 좇으면 우리 축을 버리고 열세인 축에서 경쟁하게 된다 |
| **S14 Workbench · S16 CTK** | 플랫폼·확장 API 는 생태계 자산이다. 기능이 아니라 **수십 년의 사용자·협력사 축적**이 본체다 |
| **S15 HPC 라이선스** | 라이선스 모델 자체가 우리에게 없다(SaaS). 병렬화는 필요하면 하되 「4코어 라이선스」라는 형태로는 아니다 |
| **D1~D4 Discovery 전체** | 실시간 GPU 시뮬레이션 + 3D CFD 는 각각 독립 제품 규모다. **3D Navier-Stokes 솔버는 우리가 만들 것이 아니다** |
| **C1 Windows 데스크톱** | 웹이 우리 배포 모델이다. 데스크톱은 요구가 확인되면 별개 제품으로 검토한다 |

**총평**: 이 사양서에 정면 대응하는 것은 **권하지 않는다.** 격자·플랫폼·라이선스 축에서
구조적으로 미달이고, 그 격차는 기능 추가로 좁혀지지 않는다.

우리가 실제로 강한 축은 다르다 — **파라메트릭 형상 → 자동 격자 → 해석 → 판정을
사람 개입 없이 한 번에 도는 것**, 그리고 **판정의 정직성**(추정을 추정이라 표시하고,
미측정을 통과로 세지 않는 것). ANSYS 는 그 자동화를 사용자가 수행한다.

따라서 이 문서의 계획은 **「ANSYS 를 따라잡기」가 아니라 「우리 자동화 루프의 해석 품질을
올리기」**로 읽어야 한다. 4.0(STEP 직접 투입)과 4.1 이 그 성격이고, 4.3 부터는 성격이
달라지므로 개별 판단이 필요하다.

---

## 6. 재평가 기준

이 문서는 다음 중 하나가 발생하면 다시 본다.

- 실제 고객이 **특정 미충족 항목 때문에** 도입을 못 한 사례가 나올 때 (항목명과 함께 기록)
- 4.0(STEP 투입)이 끝나 격자 항목의 실제 난이도가 재측정될 때
- FEA 정확도 검증 케이스(A1~A5)가 확장돼 현재 오차 수준이 갱신될 때

⚠ **사양서에 항목이 있다는 사실만으로는 재평가 사유가 아니다.**
