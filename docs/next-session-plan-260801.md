## 3. ★ C(분류기)에 대한 정직한 결론 — **커버리지를 바꾸지 않았다**

코퍼스 STEP 35건 전수(`measureClassifierCoverage()` — 리포에 고정했다):

```
바디 있음 0 · 없음 35
미지원 사유  1위 non-linear edge (CIRCLE)          61건  ← 원호 엣지
            2위 no FACE_OUTER_BOUND                 9
            3위 B_SPLINE_CURVE_WITH_KNOTS           6
            4위 TOROIDAL_SURFACE                    1
       축 제약에 걸린 것                            1
```

프리즘 검출기를 3주축으로 넓힌 것은 **옳은 수정이다**(X/Y 압출 프리즘을 이유 없이 버리던
것을 없앴고 `at.rotateDeg` 로 자리도 맞춘다). 하지만 **코퍼스 커버리지는 0 → 0 이다.**
병목은 축이 아니라 **원호 엣지**였다.

측정을 임시 스크립트로 버리지 않고 리포에 넣은 이유가 이것이다 — 안 적어 두면
다음 세션이 다시 「어휘를 늘리자」로 돌아간다.

### ★ ⑥ 살(picket) 배치를 네 번 시도하고 **되돌렸다**

```
① 기둥과 같은 밑면 z    → 살이 위쪽 디딤판을 파고들어 간섭 104건
② 기둥 사이 베이별 배치 → x 가 다른 디딤판으로 넘어가 간섭 40건
③ 디딤판별 독립 배치    → 경계마다 벌어져 순간격 146.7mm (기준 100 초과)
④ 전 구간 균일 피치     → 중간참에 부재가 없어 순간격 1,250mm + 간섭 6건
```

경사·다플라이트·중간참 계단의 법정 살 배치는 **별도 설계 작업**이다. 억지로 붙이면
간섭이 남고 간격 판정이 **거짓 미달**을 낸다 — 판정을 만들려고 형상을 지어내는 것이라,
검사가 「살이 형상에 없다 — 판정하지 않았다」로 남는 편이 정직하다.
게이트 self-test 가 매번 잡았고(104 → 40 → 0+거짓판정 → 6), **되돌리는 것이 답이었다.**

버리지 않은 것 — 검사 쪽 수정 3건은 모두 옳아서 남겼다:
 · **기둥도 빈틈을 막는 부재**로 센다(살만 세면 기둥 자리가 빈틈으로 오판된다)
 · **난간 줄(run)별로 따로 잰다**(좌·우 난간을 한 줄로 섞으면 1,082mm 같은 없는 결함이 생긴다)
 · **일체 난간벽**(기둥 없는 1,100mm 콘크리트 난간) 지원 — 가장 흔한 형태였는데 빠져 있었다
 · 빌더 폴백(1,000)과 템플릿 기본값(1,200)을 **함께** 맞췄다 — 한쪽만 고치면 경로에 따라 갈린다

## 6. 다음에 할 일

### P0 — 어휘에 **소비자**를 만든다
1. **미사용 어휘 19종을 전수 분류한다** — 「의도적 API 전용」 / 「소비자 누락」.

   분류 결과를 **어휘 힌트에 적어** 다음에 또 세지 않게 한다.
2. **`extrude_profile` 을 쓰는 템플릿을 만든다.** 코퍼스 압출의 67.6%가 이 형태인데
   우리 템플릿은 0개다. 후보: 임의 형상 브래킷·거셋 변형·계단 스트링거 절단면.
   ⚠ 「쓰기 위해 쓰는」 템플릿은 만들지 않는다 — rectangle 로 충분한 것을 임의 폴리곤으로
