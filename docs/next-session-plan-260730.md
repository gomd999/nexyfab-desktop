## 2. 이번 실측이 새로 찾은 것 — **판정이 도달했는데 무엇인지 모른다**

지금까지 이 세션은 「판정이 소비자에 **닿는가**」를 고쳐 왔다. 이름으로 세어 보니
그 다음 단계가 드러났다: **닿았는데 무엇을 판정했는지 읽을 수 없다.**

```
실측 문서(rc_frame 안전검토.html):
  checks ductility 판정: 적합 ✓ eps_t=0.01 · min_allowed=0.00 · section=인장지배
         flexure   판정: 적합 ✓ Mn_kNm=387.71 · phi=0.85 · ratio=0.22
         shear     판정: 적합 ✓ Vc_kN=134.72 · Vs_kN=208.27
```

한국어 문서인데 **판정 항목명이 영문 코드 키**다. 값은 정확한데 「무엇을 판정했는가」가
읽히지 않는다 — 제작 업체·건축주가 받는 문서다.

**기계 0% 가 중요한 대조군이다** — `mech-check` 는 모든 검사에 `labelKo` 를 붙였다.
즉 **가능한 일이고, 하지 않은 것**이다.

상위 키: `flexure`×6 · `shear`×6 · `travel`×5 · `lines[0..3]`×4씩 · `slope`×4 ·
`stack`×4 · `vent`×4 · `rho`×3 · `pm`×3 · `ductility`×3 · `deflection`×3

원인: `rc_beam`·`drainage_vent` 등 **계산기가 `checks: {flexure: {...}}` 로 반환**하고
`labelKo` 가 없어, 렌더러가 객체 키를 라벨로 쓴다.

### ⚠ 이름 없는 판정 5건

라벨이 **빈 문자열**인 판정이 5건 있다(건축·교량). 키조차 못 얻은 것이라
문서에 "판정: 적합 ✓" 만 덩그러니 나온다 — 무엇의 판정인지 알 방법이 없다.
