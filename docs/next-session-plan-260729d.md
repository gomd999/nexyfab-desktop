## 4. 다음 세션의 측정 방법 제안

이번 세션에 측정으로 세 번 틀릴 뻔했고, 전부 **표시 계층을 통해 셌기 때문**이다.
다음은 방법을 바꾸는 것이 낫다:

1. **검사 트리를 직접 순회**한다(HTML 을 거치지 않음). `runDomainSafetyCheck` 를 export
   하거나 감사용 진입점을 만든다 — 표시가 바뀌어도 측정이 흔들리지 않는다.
2. **판정 항목을 이름으로 나열**해 세션 간 diff 를 뜬다. 수치만 비교하면 「무엇이 늘고
   무엇이 사라졌는지」를 놓친다.
3. **쉬운요약(소비자 문서)에 도달한 것**을 따로 센다. 이 세션의 결함 대부분이
   「계산은 됐는데 소비자에 안 닿음」이었는데, 그건 안전검토.html 만 봐서는 안 보인다.
