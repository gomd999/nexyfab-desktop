# NexyFab 관리자 6개 언어·RTL 계획

작성일: 2026-08-19

## 현재 상태

- 사용자 화면은 `kr/en/ja/cn/es/ar` 6개 언어와 아랍어 RTL을 지원한다.
- 관리자 화면은 `/admin` 단일 라우트이며 한국어 문자열과 `ko-KR` 포맷이 다수 남아 있다.
- 관리자 인증·권한·API 동작은 언어 변경과 분리해야 한다.

## 목표

관리자 URL을 깨뜨리지 않고 `/admin`에서 다음 6개 언어를 제공한다.

- 한국어(기본): `kr/ko`
- 영어: `en`
- 일본어: `ja`
- 중국어: `cn/zh`
- 스페인어: `es`
- 아랍어: `ar` + RTL

## 선택한 구조

관리자 전체 라우트를 `/admin/[lang]`으로 복제하지 않고, `/admin` 경로를 유지한다.

- `nf_admin_locale` 쿠키를 서버 레이아웃이 읽는다.
- 관리자 내 언어 선택기를 공통 내비게이션에 둔다.
- `AdminI18nProvider`가 현재 언어와 `t()` 함수를 하위 화면에 제공한다.
- 기본 언어는 `kr`, 잘못된 값은 `en`이 아니라 `kr`로 안전하게 폴백한다.
- `html lang`과 `dir`을 쿠키 언어에 맞춰 설정한다.

## 단계별 실행

### 1단계 — 기반 계약과 포맷

- 관리자 언어 타입·정규화·RTL helper 추가
- 관리자 번역 카탈로그 스키마 고정
- 날짜·시간·숫자·통화 formatter를 현재 언어에 연결
- 기존 API/인증 흐름이 영향을 받지 않는지 타입검사

### 2단계 — 공통 관리자 셸

- `AdminLayout`, `AdminNav`, 로그인/세션 컨트롤 번역
- 언어 선택기와 쿠키 저장
- RTL에서 사이드바·메인 영역·아이콘 방향 검증
- 공통 로딩·에러·토스트 문구 번역

### 3단계 — 핵심 운영 화면

다음 순서로 번역한다.

1. 회원·관리자 이메일·보안
2. 구독·청구·환불
3. RFQ·견적·제조사·계약
4. AI 사용량·비용·Provider/API Health
5. 감사 로그·이메일 로그·웹훅·검색

### 4단계 — 파트너·운영 화면

- 파트너·정산·KPI·SLA·릴리즈·템플릿·문의 화면 번역
- 표·필터·상태 배지·CSV/날짜/금액 포맷 점검

### 5단계 — RTL·접근성·회귀 테스트

- 아랍어에서 `dir="rtl"`, 논리 CSS 속성, 표 정렬, 화살표·아이콘 확인
- 6개 언어별 핵심 관리자 경로 렌더링 테스트
- 한국어 누출·빈 번역·영어 fallback 의도치 않은 발생 검사
- 관리자 인증 실패/성공, 언어 변경 후 세션 유지 테스트

## 품질 게이트

- 신규 관리자 사용자 문구는 6개 언어 항목을 모두 가져야 한다.
- `ko-KR` 같은 하드코딩 locale은 허용하지 않는다.
- 기존 `/admin/...` URL과 관리자 API 계약은 변경하지 않는다.
- `npm run typecheck`
- 전체 i18n 감사 테스트
- 관리자 핵심 경로 6개 언어 브라우저 스모크 테스트

## 배포 순서

1. 카탈로그·공통 셸을 staging에서 검증
2. 핵심 운영 화면을 순차 활성화
3. 관리자 본인 계정으로 6개 언어·RTL 확인
4. 사용자 화면 회귀 확인
5. 별도 배포 승인 후 production 반영

결제·사용자 인증·관리자 권한 정책은 이 작업에서 변경하지 않는다.
