> 재현 스크립트: `scripts/dogfood/` (시나리오1=Pro CAD 경로 `0*.test.ts`, 시나리오2=라이브
> 도면집 경로 `2x-*.mjs`). **소스 무수정 탐색**으로 수집.

## 관통하는 패턴 (이게 핵심 진단)

> **테스트가 통과하는 이유는 각 단계가 자기 계약을 지키기 때문이고,
> 실사용이 깨지는 이유는 단계 사이에 계약이 없기 때문이다.**

- 홀 IR 도 z=0 기준이 맞고 압출 IR 도 z=0 기준이 맞는데 **둘의 "기준"이 다른 면**을 가리킨다
- 질량 모델은 중실 box 로 일관되고 규격 스냅도 정확한데 **둘을 대조하는 곳이 없다**
- `structural` 은 경고를 정확히 계산하고 `easySummary` 는 받은 필드를 정확히 쓰는데
  **경고 필드를 아무도 안 읽는다**

→ 앞으로 필요한 것은 각 모듈의 정확도가 아니라 **모듈 경계의 교차 검증**이다(C1 프록시
인벤토리가 어휘에 했던 일을, 파이프라인 단계 사이에 해야 한다).

### F1 · 한 페이지 안에서 자기모순 (발주 규격 ↔ 질량)

둘 중 하나는 반드시 틀렸다: 라벨이 거짓이거나 질량이 거짓.

## F14 · 어셈블리 API 표면이 자기 이름과 어긋난다 (탐색 중 발견)

도그푸딩 탐색 파일 5개가 **컴파일되지 않았다.** 실패 사유 자체가 발견이다 — 설계자가
자연스럽게 쓸 법한 호출이 전부 타입에서 거부됐다:

| 기대한 호출 | 실제 |
|---|---|
| `import { solveMates } from '@/lib/assembly/mateSolver'` | **해당 export 없음** |
| `{ partId: ... }` 로 부품 인스턴스 지정 | `PartInstance` 에 `partId` 필드 없음 |
| `result.converged` · `result.parts` | `IterativeSolveResult` 에 두 속성 다 없음 |
| `linearPattern({count, spacing, direction})` | `LinearPatternOptions` 와 불일치 |
| `StepGeometryInput` 을 어셈블리 상태로 전달 | `never` 로 좁혀짐 |

즉 **엔진은 훌륭한데(솔버 1,198줄·해석적 야코비안) 그 앞에 설 수 있는 문이 없다.**
커버리지 감사가 "어셈블리 mate = A등급"으로 본 것은 UI 경로 기준이었고, **프로그래밍
경로는 사실상 진입 불가**다. AI 에이전트가 운전하는 제품을 지향한다면(전략 §6) 이건
UI 배선보다 먼저 고쳐야 한다.

→ **W5-F 에 편입**: mate 실구현과 함께 **공개 API 표면 정리**를 범위에 포함.
탐색 파일은 컴파일되지 않아 재현 능력이 없으므로 보관하지 않는다(사유는 위 표에 보존).
동작·컴파일되는 재현만 `scripts/dogfood/` 에 남긴다.

## F15 · 불리언이 든 트리는 저장→로드가 불가능하다 ★치명 (신규)

```
deserializeFeatureTree(serializeFeatureTree(tree))
→ { ok:false, error:"invalid_payload",
    message:'node[4].payload.kind="boolean" is not a known FeatureKind' }
```

`boolean` 은 `FeatureKind` 열거형에 있고 `replayTree` 가 렌더하는데 **persist 검증기만 모른다.**
결과: 불리언으로 조립한 모델은 화면에는 나오지만 **저장할 수 없다.**

특히 오늘 작업과 직결된다 — W2-A 가 hole·rib 을 리프로 확정하면서 그 근거로
`boolean{difference}(extrude, hole)` 이 전파됨을 증명했는데, **그 트리 자체가 저장 불가**다.
즉 "구멍 뚫은 부품"을 저장할 수 없다.

재현: `scripts/dogfood/02-bracket-solid.test.ts` B 케이스(`it.fails` 부채 표식으로 고정).
