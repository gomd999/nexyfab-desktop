# ADR-017 — 위상 명명 K2.2 스파이크 + 피처 트리 OCCT 수렴

**Status:** proposed · **Date:** 2026-07-19 · **Risk tier:** P1
**Builds on:** [ADR-013](013-own-pro-cad-track.md)(Path A 확정) · [ADR-014](014-occt-kernel-promotion.md)(K1~K7) · [ADR-016](016-kernel-of-record-and-engine-selection.md)(커널 오브 레코드)
**Strategy:** [`docs/strategy-path-a.md`](../strategy-path-a.md)

## Context

260719b 코드 실사에서 두 가지가 드러났다.

**(1) 자산은 문서보다 훨씬 앞서 있다.** `src/lib/sketch`·`assembly`·`cad` 3스택 **1,549 테스트 통과**.
2D 구속 솔버(planegcs 12구속·DoF·드래그), 어셈블리 mate 솔버(Lagrangian Newton-LM + 해석적
Jacobian + 그룹 분해, mate IR 11종), 피처 히스토리(EditOp 7종 — 중간 삽입·재정렬·suppress)가
**전부 실제로 구현·검증**되어 있다. `OWN_PRO_CAD.md` 는 Phase 3 을 "2027 미착수"로 표기하나
사실과 다르다. ADR-016 은 Path A 자산이 `src/lib/occt` K1~K7 에 있는 것처럼 읽히나, 실제 자산은
`src/lib/cad`·`sketch`·`assembly` 에 있다(K-시리즈 `variableFillet`·`draft` 가 UI 미배선이라는
서술 자체는 사실).

**(2) 남은 리스크는 사실상 두 개다.**

- **R1 위상 명명 K2.2** — `topoNaming.ts` 는 extrude 전용 생성-이력 명명이고, 파일 헤더가 스스로
  범위를 밝힌다: *"Booleans split + merge faces … (K2.2) — out of scope here."*
  실 OCCT 경로는 별도의 기하 시그니처 매칭(`edgeCorrespondence.ts`)을 쓴다. **불리언·필렛이 면을
  쪼갠 뒤의 참조 생존은 어느 쪽도 보장하지 않는다.**
  또한 `topoNaming.test.ts` 의 "stable across a rebuild" 테스트는 독립 토폴로지 2개를 비교하는
  **항진명제**라 회귀 안전망 역할을 못 한다(구성상 참인 성질이라 무해하지만 검증은 아니다).
- **R2 이음매** — **피처 트리가 OCCT 로 재생성되지 않는다.** 트리는 TS 폴리헤드론/SCAD 로만
  재생성되고, 실 B-rep(63MB WASM·op 15종)은 `shape-generator` 쪽 별도 파이프라인에 있다.

R2 를 닫지 않으면 세 스택(T1 drawing-to-3d · T2 Pro IR · T3 OCCT)이 갈라진 채 각자 늙는다.
R1 은 연동 도면·히스토리의 실사용 품질을 좌우한다.

## Decision

### D1. 위상 명명은 "완벽 재현"이 아니라 "검증 가능한 참조"로 정의한다

Parasolid 급 영속 ID 재현을 목표로 하지 않는다. 대신:

- 기하 지문 매칭 결과에 **신뢰도**를 산출한다.
- 신뢰도 미달·다중 후보면 **조용히 추측하지 않고 명시적으로 참조 상실을 보고**하고 재지정을 요구한다.
- 재생성마다 **참조 생존율**을 산출해 리포트한다(A1/B1/C1/D1 검증층과 동일 사상).

근거: 이 저장소의 불변 원칙(생성≠검증·날조 금지·거부는 이유와 함께)과 정합하며, **AI 가 형상을
편집하는 제품에서는 조용히 틀린 모델보다 되묻는 편이 옳다.** 경쟁 제품 대비 열위가 아니라
차별점으로 성립한다.

### D2. 스파이크로 실측한 뒤에만 로드맵을 확정한다 (1~2주 타임박스)

**측정 대상**

| # | 시나리오 | 측정값 |
|---|---|---|
| S1 | extrude → 상류 치수 변경 → 재생성 | 면·모서리 참조 생존율 |
| S2 | extrude → **불리언 컷 삽입** → 상류 치수 변경 | 생존율 · 오매칭율 |
| S3 | 필렛 적용 → 상류 치수 변경 | 필렛 참조 생존율 |
| S4 | 피처 **중간 삽입/재정렬**(EditOp) 후 재생성 | 생존율 |
| S5 | revolve/pattern | 명명 커버리지(현재 0) |
| S6 | 파라미터 대폭 변동(×0.2~×5) | 붕괴 지점 |

**핵심 지표 2개**
- **생존율** — 재생성 후 참조가 유지된 비율
- **오매칭율(silent mismatch)** — 잘못된 엔티티를 **조용히** 잡은 비율. ★이게 진짜 지표다.
  생존율이 낮아도 오매칭이 0 이면 D1 방침으로 제품화 가능하다. 반대로 오매칭이 있으면 치명적이다.

**성공 기준**
- S1~S4 **오매칭율 0%**(필수 — 하나라도 있으면 D1 전제가 깨진다)
- S1 생존율 ≥ 95% · S2/S3 ≥ 70% · S4 ≥ 80%
- 미생존 케이스가 **전부 "참조 상실"로 검출**될 것(무성 실패 없음)

**실패 시 대안 경로(사전 확정 — 실패해도 표류하지 않게)**
- (a) 오매칭 > 0 → OCCT `BRepTools_History` 기반 generation/modification/deletion 추적으로 전환
  (비용 크지만 커널이 주는 정보라 정확)
- (b) 생존율만 낮음 → D1 방침 유지 + 재지정 UX 를 1급 기능으로 승격(참조 상실 목록·원클릭 재지정)
- (c) 둘 다 나쁨 → **연동 도면·히스토리 편집을 접고** "재생성형(파라미터 우선)" 강점을 극대화.
  T1 drawing-to-3d 가 이미 그 모델이고 잘 작동한다 — 후퇴가 아니라 다른 제품이다.

### D3. 스파이크와 병행해 R2 이음매를 설계한다

`featureTree` replay 가 `occtEngine`/`solidKernel` 을 호출하도록 배선. 스파이크 결과가 (c) 로
나오더라도 이 배선은 유효하다(B-rep 산출물 품질·STEP 정확도가 올라간다).

## Consequences

### Positive
- 로드맵 리스크가 **모호한 다년 과제 → 2주 안에 판정 가능한 실측 문제**로 축소된다.
- 실패 경로가 사전 확정되어 있어 어떤 결과가 나와도 다음 행동이 정해진다.
- D1 방침은 검증층 자산(A1/B1/C1/D1)을 그대로 재사용하며 제품 서사와 일관된다.

### Negative / 감수
- D1 은 SolidWorks 대비 "가끔 다시 지정해야 함"을 사용자에게 노출한다. 정직하지만 마찰이다 →
  재지정 UX 품질이 곧 제품 품질이 된다.
- OCCT 커널 자체의 필렛·불리언 견고성 한계는 이 ADR 로 해결되지 않는다(전략 문서 §5 포기 목록).

### 후속 문서 정정 (별건)
- ADR-016 — Path A 자산 위치 서술 보정(K-시리즈 미배선 서술은 유지).
- `docs/roadmap/OWN_PRO_CAD.md` — Phase 2.7·3.1~3.6 실제 진척 반영(현재 약 1년 6개월 뒤처짐).

## 판정 기준 요약

> **오매칭율 0 이면 간다. 오매칭이 있으면 커널 이력 추적으로 전환한다. 둘 다 안 되면 재생성형으로 간다.**
