# Complex-product holdout acquisition

## Purpose

The commercial benchmark requires 20 independent product lineages for each of
six complex-product families. The frozen corpus currently has 88 of 120 cases.
The remaining slots are robot 11, gearbox 3, pressure vessel 9, and
turbomachinery 9.

New files do not become benchmark truth merely by being copied into a folder.
They must pass the acquisition validator first, then native extraction,
assertion review, and the existing dual ground-truth approval workflow.

## Acquisition boundary

Use CAD from a manufacturer, owner, or another source whose terms explicitly
allow the intended commercial evaluation. Do not use screenshots, videos,
PDF-only drawings, AABB approximations, or CAD regenerated by the model being
evaluated as sole ground truth.

Each submission must provide exactly one independent product lineage per slot.
Archive files and their extracted members count as one lineage. The same source
hash, product lineage, or source file cannot be reused across families.

Keep new holdout files outside the application repository and model-development
workspace. Record the release-candidate freeze before acquiring or opening the
files. Access must be limited to the evaluation and review workflow.

## Required submission

Create a JSON document with schema
`nexyfab.holdout-acquisition-submission.v1` and these top-level fields:

```json
{
  "schema": "nexyfab.holdout-acquisition-submission.v1",
  "modelFreeze": {
    "releaseHead": "40-character Git commit",
    "frozenAt": "ISO-8601 timestamp",
    "receiptHash": "SHA-256 of the signed freeze receipt"
  },
  "records": []
}
```

Every record maps to one slot in
`docs/evidence/complex-holdout-lineage-v2-260807/shortfall-acquisition-queue.json`
and contains:

- slot, family, independent lineage, relative file path, extension, byte size,
  SHA-256, and acquisition timestamp;
- authoritative HTTPS source, provider, license identifier/URL, explicit
  commercial-use decision, and signed provenance review artifact hash;
- training, fine-tuning, and prompt-development exclusion attestations plus a
  signed access-control/isolation review by a different reviewer;
- governed native extractor name, definition/occurrence/transform/joint counts,
  extraction receipt hash, and signed structure review;
- an additional approved format review when a conditional format is used.

The hashes bind review artifacts; they are not themselves proof that a reviewer
is qualified or that a signature is authentic. Preserve the signed originals in
the controlled review system.

## Validate

```powershell
$env:NEXYFAB_HOLDOUT_ACQUISITION_ROOT = 'D:\controlled-holdout'
npm run evidence:holdout-acquisitions:validate -- `
  --submission=D:\controlled-holdout\submission.json `
  --out=docs\evidence\complex-holdout-lineage-v2-260807\acquisition-validation.json
```

The command recomputes source size and SHA-256 from disk, enforces safe relative
paths, compares the submission with all 88 frozen cases, and emits a redacted
receipt. It exits non-zero until all 32 slots are valid. A passing receipt sets
`readyForCuration=true`, while `grantsGroundTruthApproval` and `scoreEligible`
remain false.

## Promotion sequence

1. Run native extraction and preserve its immutable receipt.
2. Build assertion graphs and tolerance policies from the acquired sources.
3. Run the existing ground-truth queue and domain/independent dual review.
4. Recheck lineage isolation and campaign split before any model execution.
5. Promote only the approved cases into a new immutable corpus version.
6. Run the 120-case campaign without exposing expected answers to the model.
