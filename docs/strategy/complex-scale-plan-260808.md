# 복잡·대규모 대응 계획 — 고층건물(내부 전체)·복잡 교량·복잡 인테리어·복잡 제품 (2026-08-08)

상위: [domain-accuracy-95-plan-260808.md](./domain-accuracy-95-plan-260808.md)(정확도 계약)와 병렬로 가는 **스케일 확장 트랙**. 95% 계약은 "만든 것이 정확한가", 이 계획은 "얼마나 복잡한 것까지 만들 수 있는가"를 다룬다. 범례 동일: 👤=사용자 전용, 🤖=에이전트.

## 0. "대응된다"의 정의 (전 목표물 공통 6요건)

1. **생성**: 자연어/도면 → 해당 복잡도의 3D 형상 (AI=결정, 코드=전개)
2. **검증**: 스케일에서도 결정론 게이트 작동(간섭·연속성·법규성 검토·피난)
3. **도면/GA**: 레이어·시트 분할된 2D/3D 산출물
4. **BOQ/물량**: 부분합=전체 교차검증되는 물량
5. **성능**: 뷰포트 예산 내 렌더(S/M/L/XL 등급 매핑)
6. **정확도 축 편입**: hierarchy/occurrences 축의 95% 캠페인 케이스로 측정 가능

## 1. 현재 상한 (260808 실측)

- 템플릿 최대 부품수: **113**(tower_crane) / masonry_wall 99 / fence_run 109 / ceiling_grid 95 / commercial_massing 79 — **수백 부품대 진입 전**
- 토목은 특히 얇음: 3템플릿, 최대 4부품 (계산엔진은 강하나 형상 어휘 부족)
- 복합제품 STEP **임포트**는 17,269부품 통과 실측(참고 코퍼스) — 생성이 아니라 소비만 가능
- 뷰포트 계측: XL 1.1M triangles 파이프라인 가동(GPU 예산 인증은 👤 장비 대기)
- 정확도 계약에 hierarchy·occurrences·body_membership 축 **이미 존재** — 측정할 준비는 됨
- **구조적 병목 5개**:
  1. 계층 IR 부재 — assembly가 flat `parts[]` (서브어셈블리·재사용 정의 없음)
  2. 인스턴싱 부재 — "기준층 ×20층"을 부품 복제로만 표현(데이터·렌더 폭발)
  3. 시스템 레이어 부재 — 구조/외피/인테리어/MEP 구분 없는 단일 목록
  4. AI 단일 호출 한계 — 대형 조립을 한 번에 생성 불가(폭주·MAX_TOKENS 이력)
  5. 검증 스케일 — 간섭 O(n²)·피난 flood가 실 단위에 묶임

## 2. 아키텍처 결정 3개 (전부 🤖, N1에서 확정)

- **D1 계층 어셈블리 IR**: `definitions[]`(재사용 부품/서브어셈블리 정의) + `instances[]`(ref+transform+배열 패턴). occurrences/hierarchy 축과 1:1 정합. ⚠️기존 flat 배열을 무비판 재순회하는 하위 소비자 전수감사 필수(과거 `cs` 배열 함정과 동형 — GA·STEP·structural·BOQ·간섭 전부).
- **D2 프로시저럴 컴포지터**: 반복(층×유닛×방·경간×거더·그리드)은 **AI가 아니라 결정론 전개기**가 만든다. AI는 상위 결정만(타입 평면, 코어 위치, 유닛 믹스, 경간 분할, 부재 규격) — 검증된 파라메트릭 전개가 계층 IR을 생산. 폭주·날조 원천 차단.
- **D3 시스템 레이어**: 파트에 `system: structure|envelope|interior|mep|finish` 태그 → 레이어별 검증기·레이어 토글 GA(스키드 v3 계통색의 일반화)·시트 분할 도면.

## 4. 검증 스케일링 (🤖 — 사다리와 병행)

- **간섭 브로드페이즈**: AABB 그리드/BVH로 O(n log n) 후보 축소 → 기존 정밀검사. 층/존 단위 분할 실행
- **피난·동선 그래프**: 실→문→복도→계단 연결 그래프(기존 flood의 계층화) — 전층 도달·유효폭
- **BOQ 교차검증**: 정의×인스턴스 수=전개 합 (인스턴싱의 공짜 검증), 층합=동합
- **치수/역투영**: 전수 불가 → 대표 부재 층화 샘플링(정의당 1+무작위 재검) — 샘플링임을 명시
- **소크 확장**: 대형 어셈블리 반복 빌드 RSS 게이트(기존 stepBurnInSoak 패턴 재사용)

## 5. 렌더/성능 동반 조건

- B-L2부터 **인스턴싱 렌더 필수**(InstancedMesh — 정의당 1지오메트리), L3부터 LOD·컬링
- 레벨별 예산 매핑: L1≈S, L2≈M, L3≈L, L4≈XL(1.1M tris) — 기존 viewport 계측이 그대로 게이트
- GPU 실측 인증은 👤 장비(기존 Phase 3와 공유)

## 6. 95% 프로그램 연결

- 1차 인증(현행 계획)은 L1~L2 케이스로 층화 — 사다리와 인증이 서로 블로킹하지 않게
- L3~L4는 **2차 인증 확장**으로 편입(hierarchy/occurrences 축이 실질 변별)
- 기계 L4 ground truth = 외부 워커 57건(👤 라이선스) — 기존 G8과 동일 항목
