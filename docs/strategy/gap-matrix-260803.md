# 기능 갭 매트릭스 — 상용 CAD 20권 vs NexyFab (260803, D5)

> ▶ 리뷰어 피드백 「UI 옵션이 너무 적음」·「어떤 제품이 가능한지」에 대한 **정량 근거**.
> 기준선은 `Downloads/새 폴더 (6)/` 상용 매뉴얼 20권이고, 각 매뉴얼의 기여는 CAD 백과사전
> §0.3 「첨부 자료의 역할 지도」가 이미 요약해 뒀다(그 표를 기준으로 삼는다).

---

## ⚠ 이 문서를 만들면서 **내 주장 4건이 틀린 것으로 드러났다**

이 매트릭스는 처음에 기억과 이전 대화로 작성됐다가, 항목별로 실측하면서 계속 뒤집혔다.
그 자체가 기록할 값이 있다 — **문서는 실측 없이 쓰면 틀린다.**

| 이전 주장 | 실측 결과 | 확인 방법 |
|---|---|---|
| 「조인트/구속 = 없음」 | **있다.** `assembly-constraints.mjs` — offset·concentric·onFace·mirror·centerline. `buildAssembly:615` 가 실제로 호출한다 | `grep -n resolveConstraints assembly.mjs` |
| 「질량특성(관성) = 있음」 | **관성은 없다.** `structural` 은 질량·CG·반력·부재응력·전도까지 | `Object.keys(built.structural)` |
| 「Field-to-Finish = 없음」 | **있다.** `groundFromSurvey(elements, points)` — 측량점→지표면 | `grep -rn groundFromSurvey scripts/` |
| 「코리더 = 문자열 있음」 | **아니다.** `corridorMm` 은 선형 주변 **측방 필터 폭**이지 Civil 3D 코리더 모델링이 아니다 | `alignment-geom.mjs:339` |
| 「STEP 한글 이름 = 고쳤다」 | **안 고쳐졌었다.** 미리 이스케이프한 값을 OCCT 가 다시 이중화해 뷰어에 `\X2\…` 리터럴이 떴다 | `npx vitest run scripts/drawing-to-3d/step-assembly-tree.test.ts` |
| 「계통 태깅 = 전 경로 적용」 | **라우트·MCP 만.** 템플릿 직접 빌드는 못 받아 STEP 트리가 '부품' 한 덩어리였다 | `grep -rn autoTagAssembly scripts/ src/` |

⚠ 첫 번째가 가장 컸다 — **관계 배치 엔진이 이미 있는데 스키마·프롬프트에 없어서
아무도 못 쓰고 있었다**(템플릿 0건·AI 0건). 그것이 부유 28/42 의 근본 원인이었다.
「없다」와 「닿지 않는다」는 다르고, 후자가 훨씬 흔하다.

⚠⚠ 다섯 번째(STEP 한글 이름)는 **성격이 다르다.** 위 넷은 「몰랐다」인데 이것은
**「고쳤다고 보고했는데 아니었다」**다. 원인은 검증을 반쪽만 한 것 —
파일에 비ASCII 바이트가 0 인지만 재고 **그 이스케이프를 되돌려 한글이 나오는지 안 봤다.**
> **바이트 검사는 인코딩 검사가 아니다. 왕복(encode→write→decode)까지 재지 않은
> 인코딩 수정은 미완이다.**

이것과 여섯 번째(계통 태깅)는 같은 자리에서 만났다 — NAUO 를 만들려고 트리를 짜다가
「계통이 전부 '부품' 한 덩어리」인 것을 보고 거슬러 올라가 찾았다.
**새 기능을 실측하면 옛 기능의 거짓 통과가 드러난다.**

## 0. 「템플릿 없어도 다 만드나」 — 자유형 경로 전수 실측 (260803)

⚠ **템플릿으로 재면 안 된다.** 템플릿은 우리가 미리 만든 것이라 「된다」가 당연하다.
카탈로그에 **없는** 실무 과제를 도메인당 3건 주고, 라이브 라우트와 **같은 프롬프트**로 쟀다.

| 축 | 결과 | 뜻 |
|---|---|---|
| 게이트 에러 / 부품 | **0 / 158** | 어휘 40종이 5도메인을 다 받는다 |
| STEP NAUO 있는 것 | **12 / 12** | 조립 트리가 **템플릿 전용이 아니다** |
| STEP 비ASCII | **0** | 한글 파트명 정상(디코드 확인) |
| 재질 선언 | 12 / 12 | `material` 스키마 배선 후 |
| role 선언 | 132 / 158 | 계통 트리의 재료 |
| **부유 / 부품** | **1 / 131** | 고정 코퍼스 A/B(22→1). 남은 1은 실제 설계 오류 |
| **간섭** | **5** | 34→5. 남은 5도 실제 설계 오류(판정이 옳게 잡는다) |
| **designOk** | **7 / 11** | 0/11 → 7/11 |

⚠ 이 표의 앞 두 행이 「템플릿이 있으면 좋고 없어도 된다」의 근거다.
남은 축(부유·간섭)과 그 원인·수정은 계획서 §0.15 에 있다.

## 매트릭스

기준선: **SOLIDWORKS·Fusion 360 3권**(D0 에서 타깃을 기계설계 실무자로 확정 §8).
토목·건축·조경은 참고로 둔다.

### 기계 (Fusion 360 / SOLIDWORKS) — 주 전선

| 매뉴얼이 기대하는 것 | NexyFab | 근거 |
|---|---|---|
| 파라메트릭 설계 | ✅ | 어휘 38종 + `shape-generator` 140피처 |
| 어셈블리 | ✅ | 템플릿 55종 · `buildAssembly` |
| **조인트/구속** | ✅ **(260803 배선)** | `resolveConstraints` 5종. **엔진은 있었고 AI·템플릿이 못 쓰던 것을 이번에 배선** |
| 충돌·간섭 | ✅ | `interferences` + 체결구 관통 면제 |
| 재질·**질량**·CG | ✅ | `structural.totalMassKg` · `cgWorldMm` |
| **관성 텐서** | ✅ **(260803)** | `structural.inertia` — 전 CG 기준 kg·mm², 평행축 정리. 원기둥·구는 폐형, 나머지는 AABB 균질 근사이고 `basis` 에 **어느 방향으로 틀리는지까지** 적는다(중공·박판은 과대) |
| 응력해석 | ✅ | FEA 스위트(TET10) + 계산기 62종 |
| B-rep 오류검사 | ✅ | `buildSolidRobust` 드롭 보고 + 게이트 38 |
| **STEP 조립 트리(NAUO)** | ✅ **(260803 재수정)** | `exportAssemblySTEP` — XCAF root→계통→부품. desk_stand **NAUO 30 · PRODUCT 31 · 계통 5**(종전 NAUO 0). 템플릿 55종 계통 미분류 **0** |
| **STEP 파트명(한글)** | ✅ **(260803 재수정)** | `escapeStepNonAscii` — **쓰인 뒤** 이스케이프. 전 수정은 이중 이스케이프였다(아래 ⚠) |
| 공차·GD&T | ✅ | GD&T 6모듈 · `tolerance_stack` |
| **모션/기구 해석** | ✅ **(260803)** | `mobility`(Kutzbach) + `kinematics.solveMobility`(구속 야코비안). 4절·슬라이더크랭크·평행사변형 M=1 · 6축 로봇팔 M=6 검증. **두 방법을 나란히** 내고 갈리면 `methodsDisagree` |
| **체결부 강도** | ✅ **(260803)** | `connections` — 핀·볼트군·용접군·베어링(ISO 281). 미검토는 `pending`(통과 아님) |
| **좌굴 선별** | ✅ **(260803)** | `buckling` — Johnson/Euler + 국부 판좌굴. **선별**이고 법정 검토는 `column_buckling`(AISC 360 §E3) |
| **임의 단면 특성** | ✅ **(260803)** | `section-properties` — Green 정리. 규격표에 없는 단면(`extrude_profile`)이 계산된다 |
| **시트메탈 전개** | ⚠ | `sheet_profile` 전개장 계산은 있으나 전용 워크플로 아님 |

## 결론 — 빈 칸이 4개에서 **2개**로 (260803)

```
① 관성 텐서        ✅ 채웠다 — structural.inertia(폐형 대조 오차 0.000%, 근사는 명시)
② 모션/기구 해석    ✅ 채웠다 — mobility(Kutzbach) + kinematics(구속 야코비안), 기구 4종 검증
③ 코리더 모델링     ❌ 토목 전용. 첫 버티컬(배관 스키드)이 아니므로 우선순위 낮음
④ 데이터 트리       ❌ Grasshopper 계열 UI. 제품 방향 결정 필요(§0.10 참조)
```

**PBAS 이식 대상은 다 채웠다.** ③④는 D0 에서 확정한 첫 버티컬 밖이다.

### PBAS 0.7.3 대조 — 무엇을 가져오고 무엇을 안 가져왔나

| | 가져옴 | 이유 |
|---|---|---|
| 임의 폴리곤 단면 특성 | ✅ `section-properties.mjs` | 규격표에 없는 단면을 계산할 방법이 아예 없었다 |
| 체결부 강도 | ✅ `connections.mjs` | 「부재를 잇는 것이 버티나」를 못 봤다 |
| 구속 야코비안 | ✅ `kinematics.mjs` | Kutzbach 는 치수를 안 본다 — 여분 구속을 개수로 못 낸다 |
| 좌굴 | ✅ `buckling.mjs` (선별) | 코드 검토는 이미 있었다. **없던 것은 전수 선별**이다 |
| SI 단위 변환 계층 | ❌ **일부러 안 가져옴** | 우리는 mm·MPa·N 로 일관돼 있다. 들이면 **두 단위계 공존 경로**가 새로 생긴다 |
| 탄성 구속망(강성행렬) | ❌ 보류 | PBAS `statics.analysisCases`·`supports` 구조에 강하게 묶여 있다. 우리 어휘로 옮기려면 **하중·지점 선언 어휘부터** 필요하다 — 그것부터가 별건 |

⚠ **이식은 베끼기가 아니다.** 원본의 버그도 따라온다 — 「구속이 하나인 부재의 반대쪽 끝을
고정으로 세는」 코드를 그대로 옮겼다가 회귀에 걸렸다(캔틸레버 K 가 2.0 대신 0.5 →
좌굴 하중 **16배** 과대). 손계산 대조를 안 붙였으면 못 잡았다.

## 진입점 커버리지 — 「웹만 되는 것」이 없어야 한다 (260803)

```
                     웹 라우트   MCP(30여 도구)   CLI      비고
배치 보정             ✅          ✅ (신규)        ✅ (신규)  buildAssembly 안으로
계통 태깅             ✅          ✅              ✅        autoTagAssembly 안으로
STEP 조립 트리(NAUO)  ✅          ✅              ✅        intentToStep 안이라 자동
인스턴스 재사용        ✅          ✅              ✅        exportAssemblySTEP 안
관성 텐서             ✅          ✅              ✅        structuralCheck 안
체결부 강도           ✅          ✅ +전용도구     ✅        buildAssembly 안 + check_connection
좌굴 선별             ✅          ✅ +전용도구     ✅        buildAssembly 안 + buckling_precheck
구속 야코비안         ✅          ✅ +전용도구     ✅        buildAssembly 안 + solve_mobility
```
⚠ 신규 3종은 **코어(`buildAssembly`) 안에 두어 전 진입점이 자동으로 받게** 하고, 그 위에
MCP 전용 도구를 얹었다 — 「이 볼트군 되나」 한 건만 묻는데 전체 조립을 세우게 하면
진입 장벽이 된다. 두 경로가 **같은 함수**를 부르므로 답이 갈릴 수 없다.
⚠ 실측으로 확인한 것이다 — 배치 보정은 **웹에만** 걸려 있었다
(MCP·CLI 부유 22 · 간섭 40 · designOk 0/11 vs 웹 1 · 5 · 7/11).
**공통 처리는 진입점이 아니라 코어 함수 안에 둔다** — 진입점은 계속 늘어난다.

## 그리고 리뷰어 피드백에 대한 답

> 「UI 옵션이 너무 적음」

기능이 아니라 **발견 가능성** 문제다. 실측:
- `Studio ↔ Expert` 전환이 **이미 앱 안에 있다**(`ShapeGeneratorClientPage:47`)
- GD&T 6모듈·공차 스택·구조검증이 다 있는데 진입점이 약하다
- 그리고 이번에 확인했듯 **관계 배치 엔진처럼 「있는데 안 닿는」 것이 더 있을 수 있다**

→ D2 의 범위는 「새로 만들기」가 아니라 **「있는 것을 찾게 하기」**다.
