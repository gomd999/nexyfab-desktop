## 1. 4트랙 분리 원칙 (차용한 핵심 방법론)

한 도면에 라벨 종류를 섞지 않고 트랙별 독립 파일로 관리 — 파이프라인 단계별로 필요한 트랙만 로드:

| 트랙 | 대상 | 지오메트리 | 파이프라인 소비처 |
|---|---|---|---|
| STR | 구조 요소: 벽체·창호·출입문 (+우리 확장: 기둥·보·브레이스·베이스플레이트) | polygon + 속성 | 도면→벡터→3D 재구성 (P0 drawing-to-3d) |
| SPA | 공간(실) 영역 | polygon | 배치 이해·면적 산출(결정론)·인접 그래프 (P4) |
| OCR | 도면 텍스트: 치수·부재기호·마감 주석 | bbox + 텍스트 내용 | 도면 diff·속성 추출 검증 |
| OBJ | 배치 객체(설비·기구) | bbox | 심볼 검출 |

## 2. 파일 포맷 — COCO 호환 JSON (도면 1장 = 라벨 1파일)

```json
{
  "images": [{ "id": 1, "width": 4961, "height": 3508, "file_name": "<도면>.PNG" }],
  "categories": [{ "id": 11, "name": "구조_벽체" }, ...],
  "annotations": [{
    "id": 0, "image_id": 1, "category_id": 10,
    "segmentation": [[x1,y1, x2,y2, ...]],
    "bbox": [x, y, w, h], "area": 6557, "iscrowd": 0,
    "attributes": { "창호": "미닫이창", "occluded": false, "rotation": 0 }
  }]
}
```

- 카테고리 name = `접두사_이름` (`구조_`/`공간_`/`객체_`/`OCR`) — 트랙 판별이 이름만으로 가능
- OCR 트랙은 `attributes.OCR`에 텍스트 원문
- 속성은 자유 확장 (`"창호":"미닫이창"` 패턴) — 우리 확장: `"부재":"H-300x150"`, `"기호":"단면A-A"` 등
- train/val 분리 유지 (관행 비율 ~89:11)

## 3. #239 원본 택소노미 (참고 기록 — 아파트 도메인)

- 공간(15): 다목적공간·엘리베이터홀·계단실·거실·침실·주방·현관·발코니·화장실·실외기실·드레스룸·기타·엘리베이터 등
- 객체(5): 변기·세면대·싱크대·욕조·가스레인지
- 구조(3): 출입문·창호·벽체 / +OCR / +background

## 4. NexyFab 확장 택소노미 (자체 합성용 — 실분야)

- `구조_`: 벽체·출입문·창호 + **기둥·보·브레이스·베이스플레이트·앵커·퍼린·랙포스트·랙빔**
- `공간_`: 실분야 재정의 — **작업구역·통로·설비구역·저장랙구역** 등
- `객체_`: 장비 심볼(펌프·탱크·교반기·컨베이어…)
- `OCR`: 치수·부재기호·용접기호·표제란

## 5. 합성 GT 생성 규칙 (라벨링 비용 0의 근거)

3D 모델(자체 커널)에서 HLR 투영으로 도면 생성 시:
1. 각 피처의 투영 실루엣 → `segmentation` 폴리곤 (정확도: 기하 연산 = 정답)
2. 피처 타입/파라미터 → `category` + `attributes` 자동 기입
3. 치수·주석 배치 엔진의 출력 → OCR 트랙 자동 기입
4. 도메인 랜덤화: 선굵기·해상도·노이즈·스캔 아티팩트 증강 → 실도면 일반화
