# 복합 시스템 AI CAD 구축 계획 — 로봇·제트엔진·공장

## 1. 목표와 완료 정의

목표는 자연어·도면·참고 CAD에서 시작해 독립 부품, 서브어셈블리, 메이트, 제조 형상과 검증 증거를 가진 편집 가능한 설계를 만드는 것이다. 단일 결합 메시나 시각용 외형은 완료로 보지 않는다.

완료 등급은 다음처럼 분리한다.

1. `concept`: 외형과 구성이 설명과 대체로 일치한다.
2. `editable`: 모든 실물 부품이 독립 FeatureTree와 안정 참조를 가진다.
3. `assembly_verified`: 실제 메이트 솔버, 자유도, 정밀 간섭, 동작 검사를 통과한다.
4. `manufacturing_review`: 부품별 G0–G9와 STEP AP242 왕복 검증을 통과한다.
5. `engineering_review`: 분야별 물리 계산과 안전 검토 근거가 완성된다.

`releaseReady`는 4단계까지만 의미하며, 법정 인증이나 전문가 날인을 대체하지 않는다.

## 2. 참고 자료의 역할

- CAD 통합 백과사전: 좌표·단위·공차·B-rep·파라메트릭 모델·기계/건축 생애주기와 검증 게이트의 기준.
- SOLIDWORKS/Fusion 360/Rhino/Grasshopper 매뉴얼: 스케치, 피처, 어셈블리, 히스토리, 직접 편집과 일반/전문가 UX 기준.
- Civil 3D/MicroStation/Vectorworks/AutoCAD 자료: 대좌표, 선형, 레벨·그리드, BIM 객체, 참조 모델과 공장 부지 기준.
- PBAS 0.7.3: 접촉·커넥터·Native SI·메이트·좌굴·하중경로와 검증 구조. 아직 완료되지 않은 비선형 물리는 통과로 간주하지 않는다.
- 참고파일들: 로봇, 감속기, 모터, 펌프, 열교환기, 압력용기, 계단, 건축 모델의 실제 STEP/SAT/STL 회귀 코퍼스.
- LLM 방법론: LLM은 후보와 관계를 제안하고 최종 판정은 결정론 코드가 수행한다. 자기일관성은 후보 탐색에만 쓰고 투표를 진실로 간주하지 않는다.
- NX-JET-SHAPE: 로프트·컷어웨이·터보팬의 시각 목표. 문서가 명시한 대로 공학 정답 데이터로 사용하지 않는다.

## 3. 공통 생성 파이프라인

`요구사항 수집 → 단위/좌표 정규화 → 기능 분해 → 부품/구매품 분해 → 후보 생성 → 부품별 B-rep 생성 → 안정 위상 참조 → 메이트 → 자유도 → 정밀 간섭 → 동작 → 분야 해석 → STEP 왕복 → 완료 인증`

각 단계는 입력, 출력, 증거, 오류 코드, 되돌림 지점을 가진다. 앞 단계 증거가 없으면 다음 단계의 성공으로 승격하지 않는다.

### 오류 분류

- 요구사항: 치수 누락, 상충 조건, 단위 모호성, 성능 조건 누락.
- 분해: 빠진 부품, 구매품/제작품 오분류, 단일 Body 병합, 계층 순환.
- 형상: 스케치 미구속, 자기교차, 영두께, 비다양체, 실패한 Boolean/Fillet/Shell.
- 위상: 수정 후 면·선 참조 소실, 복수 후보, 잘못된 메이트 재연결.
- 결합: 미수렴, 과구속, 미구속 자유도, 반대 방향, 잘못된 기준축.
- 공간: 실제 중첩, 보수 검사 과탐, 조립 순서상 삽입 불가, 유지보수 공간 부족.
- 물리: 하중경로 단절, 좌굴·피로·열·진동·유동 조건 미충족 또는 미검증.
- 교환: STEP/IFC 왕복 후 부품·계층·치수·PMI 손실.

### 수리 원칙

- 검증된 상류 단계는 재생성하지 않고 실패 단계만 되돌린다.
- 확인된 치수와 사용자 의도는 자동 수리가 변경하지 않는다.
- 고정부품, 운동 기준부품, 안전 핵심 부품은 자동 이동하지 않는다.
- 의도된 접촉·압입은 부품쌍, 간섭량/공차와 사유를 명시한다.
- 동일 지문 오류 3회 또는 총 수리 예산 초과 시 중단하고 마지막 정상 버전을 보존한다.
- 수리 전후 FeatureTree, 위상 매핑, 메이트 잔차와 간섭 차이를 감사 로그에 남긴다.

## 4. Work Package

### WP0 — 기준선과 데이터 계약

- 현재 Web·CLI·MCP·API의 생성/검증 경로를 한 계약으로 고정한다.
- `DesignIntentIR`, `ProductDecomposition`, `AiAssemblyProgram`, `GenerationEvidence`의 버전과 JSON Schema를 공개한다.
- 모든 산출물에 source, confirmed/assumed, 단위, 공차, 생성기 버전과 증거 ID를 기록한다.
- 완료 기준: 같은 입력·fixture에서 네 진입점의 의미 결과와 오류 코드가 동일하다.

### WP1 — 다단 AI 플래너

- 한 번에 CAD를 생성하지 않고 요구사항 추출, 질문, 기능 구조, 부품 구조, 인터페이스 표를 순서대로 만든다.
- 치수는 confirmed/derived/assumed/unresolved로 분리하고 가정값은 제조 단계로 승격하지 않는다.
- 후보 3개를 생성해 기능 충족, 복잡도, 제조성, 검증 가능성으로 결정론적 순위를 매긴다.
- 완료 기준: 정답 코퍼스에서 필수 부품 재현율 95% 이상, 잘못 추가한 핵심 부품 2% 이하.

### WP2 — 제조 Feature 생성기 확대

- 스케치 완전구속, Extrude/Revolve/Sweep/Loft, Hole, Pattern, Shell, Rib, Draft, Fillet/Chamfer를 OCCT B-rep으로 통일한다.
- 실패하기 쉬운 피처는 사전 조건 검사와 작은 피처 순서 재배치 정책을 둔다.
- 볼트, 베어링, 기어, 모터, 실린더, 프로파일 등은 구매품 카탈로그 인스턴스로 분리한다.
- 완료 기준: 골든 부품의 치수 오차 허용 범위 통과 95%, 닫힌 단일 솔리드 99%, Feature 종류/개수 일치 90% 이상.

### WP3 — 안정 위상과 선택 채팅

- 면·선·축·부품에 persistent reference와 기하 서명을 부여한다.
- 편집 후 안전한 참조만 자동 재연결하고 복수 후보는 사용자 검토로 보낸다.
- 선택한 면/선/부품에 자연어 수정, 미리보기, 원자적 적용/취소, Undo/Redo를 제공한다.
- 완료 기준: 표준 편집 시 참조 유지율 98%, 잘못된 자동 재연결 0% 목표.

### WP4 — 결합 정확도 엔진

- 표면·축·원통·평면·기어·랙·슬롯·접선·거리/각도 메이트를 공통 인터페이스로 푼다.
- 휴리스틱 DoF를 Jacobian rank 기반 DoF/중복구속/부족구속 판정으로 교체한다.
- 표준 결합 템플릿을 만든다: 볼트군, 축-베어링, 키/스플라인, 핀, 프레스핏, 플랜지, 용접.
- 조립 순서와 공구 접근, 삽입 경로까지 검사한다.
- 완료 기준: 골든 어셈블리 메이트 수렴 98%, 잘못된 자유도 판정 1% 이하, 의도되지 않은 중첩 0건.

### WP5 — 간섭·접촉·중첩 해결

- AABB broad phase 뒤 triangle/OCCT boolean narrow phase를 필수화한다.
- 접촉, 간극, 압입, 용접 겹침, 나사 체결을 서로 다른 의미 객체로 관리한다.
- 최소 침투축과 원인을 제안하되 자동 이동은 자유 부품·비안전 부품에만 제한한다.
- 정적 자세뿐 아니라 동작 프레임, 조립 삽입 경로, 유지보수 분해 경로를 검사한다.
- 완료 기준: 알려진 실제 충돌 recall 99%, 정밀 검사 후 과탐 2% 이하.

### WP6 — 제조 및 교환 검증

- 부품별 G0–G9, 재료/공정 DFM, 공차 누적, BOM, PMI를 실행한다.
- STEP AP242 왕복 후 부품 수, 이름, 계층, B-rep, 치수, PMI를 비교한다.
- 공장/BIM에는 IFC 계층·GUID·좌표·Property Set 왕복 검증을 추가한다.
- 완료 기준: STEP 골든 코퍼스 왕복 95%, 부품 병합/누락 0건, 단위 오류 0건.

### WP7 — 정확도 측정·실패 학습

- 참고파일들의 실제 CAD를 형상 IR과 정답 계층으로 변환한다.
- train/eval/holdout을 원본 제품 단위로 분리해 누출을 막는다.
- 형상, 치수, 특징, 부품, 메이트, DoF, 간섭, 교환을 별도 KPI로 측정한다.
- 원문 설계 IP는 저장하지 않고 정규화 실패 지문과 승인된 fixture만 축적한다.
- 매 릴리스마다 동일 코퍼스 A/B와 회귀 대시보드를 실행한다.

## 5. 도메인 트랙

### Track R — 6축 산업용 로봇을 첫 골든 제품으로

1. 요구 성능: payload, reach, 반복정밀도, 속도, 설치 자세, 작업공간.
2. 구조: base, J1–J6 housing/link, motor, reducer, bearing, brake, encoder, harness, end flange.
3. 계산: DH/POE 기구학, FK/IK, Jacobian rank, 특이점, workspace, torque/inertia, 감속기와 모터 선정.
4. 검증: 전 자세 self-collision, 케이블 굽힘/꼬임, 베어링/축 결합, 엔드이펙터 접근.
5. 기준 데이터: Epson 6축 STEP, MeArm, cycloidal gearbox, motor corpus.
6. 최종 산출: 독립 부품, 서브어셈블리, 모션 스터디, BOM, 부품별 STEP.

첫 합격 목표는 6축 로봇 한 종류에서 부품 누락 0, 선언 운동 DoF 6, 정적/동작 충돌 0, STEP 왕복 통과다.

### Track J — 터보팬/제트엔진

1. NX-JET-SHAPE 외형을 concept 기준으로만 사용한다.
2. fan, LPC/HPC, combustor, HPT/LPT, shafts, bearings, cases, stators, nozzle, accessories를 독립 계층화한다.
3. 축대칭 mean-line 모델부터 시작해 블레이드는 파라메트릭 airfoil/loft/pattern으로 생성한다.
4. Brayton cycle, mass flow, pressure ratio, stage work, tip clearance, 열팽창, 축/베어링 하중, critical speed를 증거화한다.
5. CFD/고온 피로/연소 안정성 미실행 상태는 `engineering_review`를 통과시키지 않는다.
6. 단계 목표: 교육용 터보팬 컷어웨이 → 회전 가능한 어셈블리 → mean-line 성능 연계 → 상세 블레이드/냉각 유로.

### Track F — 공장/생산 시스템

1. 제품·공정·설비·건축·구조·MEP·물류를 서로 다른 모델 계층으로 둔다.
2. site/grid/level/zone, machine footprint, foundation, aisle, conveyor, robot cell, pipe/cable tray, safety fence를 객체화한다.
3. 생산량, cycle time, buffer, OEE, 물류 흐름과 설비 연결 포트를 그래프로 계산한다.
4. 충돌뿐 아니라 작업자 통로, 지게차 회전, 유지보수 envelope, 피난·소방, 배관 경사/압력손실을 검사한다.
5. Civil 3D/MicroStation 대좌표와 IFC reference federation을 적용한다.
6. 첫 합격 목표는 소형 로봇 조립 셀: 로봇·컨베이어·펜스·작업대·전기/공압 연결, 접근/동작 충돌 0, IFC/STEP 산출.

## 6. 실행 순서

### M1 — 공통 코어 폐쇄

WP0–WP3를 완료하고 생성 UI에 단계·증거·실패 원인·재시도 범위를 표시한다. `releaseReady`를 Web 생성 완료 조건에 연결한다.

### M2 — 조립 코어 폐쇄

WP4–WP5를 완료한다. Jacobian DoF, 결합 템플릿, 정밀 간섭, 조립/분해 경로를 Web·CLI·MCP·API 공통으로 제공한다.

### M3 — 로봇 골든 제품

Track R을 끝까지 통과시킨다. 로봇에서 드러난 공통 결함은 도메인 예외가 아니라 공통 코어로 환류한다.

### M4 — 제트엔진과 공장 MVP

제트엔진은 축대칭/컷어웨이 어셈블리, 공장은 로봇 셀을 먼저 완성한다. 시각적 성공과 공학적 성공을 UI에서 분리한다.

### M5 — 확장과 신뢰도

holdout 코퍼스, 실제 사용자 실패 지문, 성능/비용 예산, 장기 회귀를 운영한다. 측정 실행 기록이 없는 정확도 수치는 공개하지 않는다.

## 7. 즉시 다음 구현 묶음

1. 생성 UI에 stage/decision/releaseReady 표시와 실패 단계 재시도 버튼 연결.
2. 조립 API의 approximate DoF를 Jacobian solver 결과와 함께 반환.
3. `standardConnection` IR과 축-베어링/볼트/핀/압입 4종 컴파일러 구현.
4. 참고파일들에서 로봇·감속기·모터 fixture 목록과 정답 manifest 작성.
5. 첫 6축 로봇의 요구사항·부품 구조·메이트·허용 DoF 골든 JSON 작성.
6. Web·CLI·MCP·API 로봇 생성 E2E를 동일 fixture로 실행.

이 순서는 복잡한 외형을 더 많이 생성하는 것보다 제조 가능한 조립의 정확도를 먼저 닫는다. 로봇 골든 제품이 통과하기 전에는 제트엔진이나 공장 전체를 자동 제조 가능하다고 표시하지 않는다.
