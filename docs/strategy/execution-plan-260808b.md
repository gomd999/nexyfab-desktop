# 정교화 실행 계획 260808b — 95% 인증 준비 완성 + 복잡도 사다리 상위 티어

상위 문서: `domain-accuracy-95-plan-260808.md`(인증 계약·G-게이트) · `complex-scale-plan-260808.md`(사다리 정의). 이 문서는 두 계획의 **잔여분만** 의존 순서로 재배열한 실행 계획이다. 완료분은 95%플랜 §1.5 표가 정본.

## 0. 현재 위치 (260808b 실측 스냅샷)

- **커널 트랙 K1~K7 완료**(K7은 S5 강등 판단만 잔여 — 텔레메트리 증거 대기). 코퍼스 16시드·소크 40반복 그린.
- **사다리 도달점**: A-L2 · B-L4(MEP, 커튼월 제외) · C-L3(±3% 구배+신축이음) · D-L3. 검증 인프라(브로드페이즈 20k·3D OBB SAT·계층 게이트 검사트리 편입) 상시.
- **인증 파이프라인**: 체인 전 구간 실동작 실증(5도메인 드릴 14/14). 병목은 실행기 판정 폭(v1=재빌드 결정론 4축)과 👤 원료(리뷰어·홀드아웃).
- **원칙 불변**: 95% 계약 무변경 · 측정 불가=not_run · 내부 템플릿=인증 부적격 · "95% 정확도" 공개 주장은 독립 홀드아웃 통과 전 금지.

## 1. 실행 웨이브 (의존 순서 — 전부 🤖, 각 항목=커밋 가능한 단위)

### W-1. 인증 실행기 실전화 (최우선 — 👤 원료 도착 즉시 캠페인 가능 상태 만들기)

v1 실행기는 "템플릿 재빌드 결정론"만 판정한다(드릴용). 실 캠페인의 판정 주체는 **AI 생성 파이프라인**이다.

| # | 항목 | 내용 | 게이트(완료 기준) |
|---|---|---|---|
| W1-1 | AI 생성 주체 배선 | 실행기가 케이스의 소스 사양(텍스트/도면)으로 `assemble`/`compose` 파이프라인을 실호출 → 산출물을 케이스 ground truth와 축별 비교. AI 호출 실패=해당 run 정직 fail(재시도는 캠페인 러너 소관) | 드릴 재실행에서 AI-주체 모드 동작 + 튜닝 미사용 플래그 유지 |
| W1-2 | step_roundtrip 축 실측정 | 산출물 STEP 방출→재임포트→부품수·체적 대조(burn-in 기계 재사용) | 축 not_run→pass/fail 전환, 드릴에서 measured 5축째 |
| W1-3 | features/hierarchy/transforms 축 실측정 | 계층 IR `_occ` 경로·패턴 전개·부품 배치를 GT와 축별 대조(어셈블리 케이스) | measured 축 8+/도메인(조인트 없는 도메인 기준 8~10) |
| W1-4 | repair 축 = 결함 주입 시나리오 | 케이스에 주입 결함(간섭·미달 구멍) 명세 → 게이트가 검출+수리 경로 제안하는지 판정. **검출 실패=falseClear 기록**(0 계약 직결) | 주입 케이스에서 falseClear 카운트 실동작 |
| W1-5 | 후보 풀 40+/도메인 | 템플릿 파라미터 스윕 확대(현 20). G7 재캠페인 규정(같은 케이스 재사용 금지) 대비 | 5도메인 × 40 클린 후보 |

완료 기준: **드릴을 AI-주체 모드로 재실행했을 때 리포트의 measured 축이 4→8+로 오르고, 나머지 not_run 사유가 "홀드아웃/리뷰어 부재"로만 남는다.**

### W-4. 증거 축적·정례화 (백그라운드 — 각 루프 세션에 1항목씩 끼워넣기)

### E-트랙. 정밀 CAD 재활성 (260808b 사용자 승인 — "AI + SolidWorks/Autodesk" 포지션)

### 우선순위 통합 (두 축을 동시에 미는 순서 — E/W 웨이브에 삽입)

1. **P-1 어휘 확장**(E1 확장과 동일 항목) — **260808b 실측 스코핑**: compose 어휘 enum=revolve/extrude/cylinder/box/sphere(+op/pattern). 텍스트 평가 코퍼스의 기계 4아키타입 중 현 변환기 커버 **1/4**(판+볼트홀만). 슬라이스 순서=커버리지 구매량 순:
   - **P-1a 원통 몸체**(축·파이프 → **2/4→3/4**): shape:'circle' 베이스는 programToFeatures 기지원 — 변환기만 확장. ⚠️**규약 충돌 발견**: box 케이스의 "(0,0) 구멍=위치 미부여 거부" 관례가 원통 동심 구멍(중심=(0,0)이 정답)과 충돌 → 몸체 종류별 규약 분기 필수(원통은 (0,0) 허용).
   - **P-1b polyline 프로파일**(L형·브래킷): programToFeatures에 sketchData 분기(~20줄, api.addSketchFeature 재사용).
   - **P-1c 보스/포켓**(add cylinder/box 2차 피처) · 앵글 프레임류(멀티바디)는 어셈블리 핸드오프로 별도(후순위).
2. **T-1 STEP 편집가능 임포트(#3)**: 두 축을 동시에 잠금해제(설계툴 상호운용 + AI "기존 CAD 개선" 입력). K-series importStep 실증이 토대.
3. **P-2 모델→AI 역루프**: 피처트리→FeatureProgram 역직렬화(이미 양방향 포맷 존재)→챗 컨텍스트 주입. 경쟁군이 못 하는 "왕복" 완성.

## 3. 순서 근거 (왜 이 순서인가)

1. **W-1이 최우선**인 이유: 👤 원료(리뷰어·홀드아웃)는 도착 시점을 통제할 수 없다. 도착했는데 실행기가 4축뿐이면 캠페인이 그 시점에 다시 밀린다. 실행기 실전화는 지금 전부 🤖로 가능.
2. **W-2가 W-3보다 앞**인 이유: 어휘 부족은 인증 축 커버리지(coverage ≥0.95)의 직접 원인이고, 사다리 상위 티어는 케이스 난도를 올릴 뿐 축을 새로 열지 않는다. 또한 W3-4가 W2-3(도어 스윙)을 재사용한다.
3. **W-4는 조건부**: S5는 증거(텔레메트리)가 조건이므로 일정으로 강제하지 않는다.
