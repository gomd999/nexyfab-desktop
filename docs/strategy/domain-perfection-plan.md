# 분야 완벽화 계획 — 토목·건축·인테리어·조경 (2026-07-14)

> domain-expansion-plan(§7-8)의 후속. "어휘 14종 + 비기계 어셈블리 + FEA" 완료 시점 기준,
> 각 분야가 **"설계하면 검증·물량·도서가 정직하게 따라온다"** 상태(=완벽)에 도달하기 위한 갭 정의.
>
> 원칙(불변): AI=이해, 결정론=형상·검증·물량. 하중·단가·철근을 지어내지 않는다 — 없으면
> INPUT_GATE/미산출 명시. 계산기는 KDS 원문검증 + 공표예제 게이트(§7.0, 계산기당 ≥10).

## 완벽의 5단 사다리 (분야 공통 잣대)

| 단 | 이름 | 정의 | 현재 도달 분야 |
|---|---|---|---|
| L1 | 형상 | 파라메트릭 프리셋+어셈블리 템플릿, 항상 manifold | 4분야 전부(폭 차이 있음) |
| L2 | 검증 | 형상→계산기 입력 **자동 파생** + 진짜 계산기(KDS) | building(rc_beam만 파생) |
| L3 | 물량 | 형상 물량 + **규칙 기반 형상-밖 물량**(거푸집·터파기·철근개산) | 형상 물량만(전 분야) |
| L4 | 도서 | 분야 관례 도면(축선·해치·배치도) + 리포트 | 기계식 GA 유용(관례 도면 아님) |
| L5 | 신뢰 | 공표예제 재현 ≥10/계산기, 실무자 검토 1회 | 미달(압축4·볼트2 수준) |

## ① 토목 (civil)

**보유**: 옹벽·박스컬버트 프리셋 / 옹벽 안정 계산기(Rankine, KDS 11 80 05 의무조항 검증) /
수량 룰엔진 v1(옹벽·관로·포장 → BOQ, eng-api 골든 6케이스) / KDS 코퍼스(옹벽 2·가설 3).

**갭 → 작업**:
- **C1 (P0) 형상→옹벽 계산기 자동 파생**: 지금 derive()={} — 옹벽 프리셋의 H·저판폭·벽체두께를
  형상에서 파생하고 토질(γ·φ·지지력)만 입력받게. "설계한 그 옹벽"이 검증되는 첫 토목 체인.
- **C2 (P0) 수량 룰엔진 ↔ 설계 패키지 통합**: eng-api의 옹벽/관로/포장 룰(터파기·되메우기·거푸집·
  버림콘크리트)을 drawing-to-3d BOQ에 연결 — 어셈블리 domain=civil이면 형상 물량+규칙 물량 합본.
- **C3 (P1) 어셈블리 템플릿**: 옹벽 연장 구간(벽체+저판+활동방지턱+신축이음 분절), 관로+맨홀 구간.
- **C4 (P1) 박스컬버트 구조 계산기**: 강성라멘 모멘트 분배(공표예제 있는 교재 기준) — 신규 계산기.
- **C5 (P2) 공표예제 게이트**: 옹벽 계산기 공표예제 10건(도로설계요령·구조물기초 예제집).

## ② 건축 (building)

**보유**: RC보·기둥 프리셋 / rc_frame 어셈블리(32.6t) / 계산기 3종(rc_beam 변형률적합·
rc_column_pm P-M·isolated_footing 2021 뚫림성능식 — 전부 KDS 원문검증) / 콘크리트 KDS 14 20 시리즈 7종.

**갭 → 작업**:
- **B1 (P0) 하중경로 자동 체인** ★건축 완벽화의 핵심: 슬래브 자중(형상)+활하중(용도 선택,
  KDS 41 10 05 표) → 보 검토(rc_beam) → 기둥 축력 집계(rc_column_pm) → 기둥 반력 → 기초(isolated_footing).
  structuralCheck가 이미 반력을 내므로, 반력→계산기 입력 파생만 이으면 된다. 하중조합(1.2D+1.6L)은
  KDS 원문 계수만 사용·명시.
- **B2 (P0) rc_column_pm·isolated_footing을 domain-verify에 연결**: 계산기는 있는데 분야 패널에서
  못 쓴다 — building-member에 2종 추가(기둥 b·h 형상 파생, 기초는 B1 반력 파생).
- **B3 (P1) 어셈블리 확장**: 다층·다베이 rc_frame(층수·베이수 파라미터), 벽식(전단벽), 계단.
- **B4 (P1) 철근 개산(정직 모드)**: 배근 가정(피복·간격·직경)을 **입력**받아 철근량 개산 —
  가정 없이는 미산출 유지. BOQ에 "배근 가정 기준" 명시 행.
- **B5 (P1) 슬래브 = Mindlin 플레이트 FEA**: FEA suite의 plateMindlin(4절점, 검증 테스트 있음)을
  슬래브 처짐·모멘트 검토에 연결 — TET10보다 슬래브에 정확한 도구가 이미 있다.
- **B6 (P2) 건축 관례 도면**: 축선(X1·Y1)·기둥 심선치수·단면 해치 평면도/단면도 — GA 2D의 건축 모드.
- **B7 (P2) 공표예제**: rc_beam·기둥·기초 각 10건(콘크리트구조 설계예제집).

## ③ 인테리어 (interior)

**보유**: 카페·리테일 프리셋 / cafe_room 어셈블리(가구 분해 모델) / 피난 계산기(재실·유효폭·출구) /
FF&E furniture 메타.

**갭 → 작업**:
- **I1 (P0) 벽·개구부 어휘**: wall(두께·높이)+door/window(개구 subtract) — 레이아웃이 "방"이 되는
  최소 어휘. 문 위치가 있어야 피난 검증이 형상과 정직하게 연결된다.
- **I2 (P0) 보행거리 검증**: 좌석→출구 최단 경로(장애물 우회, 그리드 BFS 결정론) — 피난 계산기의
  '거리' 항목을 형상 실측으로. (지금은 폭·인원만)
- **I3 (P1) 마감 물량**: 바닥·벽·천장 면적(개구 공제) → 마감재 BOQ(단가 없이 면적만).
- **I4 (P1) 어셈블리 확장**: 사무실(워크스테이션 그리드+회의실), 식음 주방존(후드·싱크 자리).
- **I5 (P2) 조도 개산**: 광속법(룸 인덱스·보수율 — 조명공학 표준식, 출처 명시) + 등기구 배치 제안.
- **I6 (P2) 컨셉 이미지 레이어**: Gemini image — "컨셉(비검증)" 라벨 분리(기존 방침 문서 준수).

## ④ 조경 (landscape)

**보유**: 데크보·U측구 프리셋 / 파고라·데크 어셈블리 / 배수 합리식 계산기(KDS 34 20 10) /
조경 KDS 7종 코퍼스(생육토심 표 RAG 검증).

**갭 → 작업**:
- **L1 (P0) 목재 부재 계산기**: 데크 장선·파고라 보의 휨·처짐(목구조 허용응력, KDS 41 33 근거
  인제스트 필요) — 지금 파고라를 만들어도 부재 검토가 없다(SHS 강관 계산기는 목재에 부적합).
- **L2 (P0) 파고라 풍하중 전도·기초**: 경량 구조물의 지배 하중은 바람 — KDS 설계하중 풍속압 →
  전도 FS·주각 앵커/독립기초 연결(isolated_footing 재사용).
- **L3 (P1) 식재 레이어**: 수목 배치(교목/관목/지피 심볼+규격 H×W×R 관례 표기) → 식재 수량표.
  형상은 심볼(원기둥+구 근사), 물량표가 산출물. 생육토심 검증은 코퍼스 RAG로 근거 인용.
- **L4 (P1) 포장·토공**: 포장 구간(면적·단면층) — 수량 룰엔진 포장 룰과 통합(C2와 공유).
- **L5 (P2) 배치도 관례 도면**: 평면 배치도(식재 심볼·포장 해치·레벨) — 조경 도면 모드.

## 순서 제안 (의존성 기준)

1. **Wave A (P0 체인)**: B1+B2(하중경로) → C1(옹벽 파생) → L1+L2(목재·풍하중) → I1+I2(벽·보행거리)
   — 전부 "설계한 그 형상이 검증되는" 체인 완성. 신규 계산기 2종(목재보·풍하중)은 KDS 원문검증 필수.
2. **Wave B (물량)**: C2(룰엔진 통합) → B4(철근 개산) → I3(마감) → L4(포장·토공) — BOQ가 실무 물량서에 근접.
3. **Wave C (도서·신뢰)**: B6·L5(관례 도면) → B5(슬래브 플레이트) → 공표예제 게이트(C5·B7).

각 Wave 종료 조건: self-test 그린 + 프로덕션 E2E + (계산기 신설 시) 공표예제 최소 3건 재현.
