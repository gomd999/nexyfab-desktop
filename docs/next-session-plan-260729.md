### 판정 관련 불변식 (이 세션에서 강제한 것)

- **해당 없음 ≠ 판정 불가 ≠ 이상 없음.** 셋을 섞지 말 것. 섞으면 소비자는 "입력을
  더 주면 된다"거나 "안전하다"로 읽는다.
- **판정 0개는 통과가 아니다**(`evidenceSufficient`). 실 CAD 코퍼스가 독립적으로 같은
  결론에 도달했다(`evidence_sufficient`).
- **이유를 모르면 단정하지 말 것.** INPUT 표식이 있으면 "입력 대기", 없으면 사실만.
- **판정에 비결정성을 넣지 말 것.** 벽시계 예산·시드 없는 몬테카를로 — 둘 다 이번에 걸렸다.
- **미검증을 해제하지 말 것.** 예산 초과분은 보수 유지하고 건수를 고지한다.

## 3. 이 세션에서 내가 틀렸던 것 (같은 실수 반복 방지)

측정으로 바로잡은 오진 5건. **전부 "코드를 읽고 추론"한 뒤 "실측으로 확인"하는 순서에서
확인 단계가 잡아냈다.** 추론 단계에서 멈췄으면 전부 잘못된 수정이 나갔다.

| 오진 | 실제 |
|---|---|
| 행어 면적이 원형봉에 사각 면적 버그 | 부품이 실제로 **각봉**이라 계산이 맞았다 |
| `exit_count` FAIL = 진짜 피난 발견(2회 보고) | **지어낸 밀도의 인공물**이었다 |
| `steel_canopy`·`duct_run` = role 태깅 갭 | **적용범위 밖**이었다(지붕 골조형·덕트 계통) |
| `conveyor legs:5` 를 부품 수와 대조 | `legs` 는 **벤트 조 수** — 단위가 다르다 |
| 판정 0개를 전부 "대상 없음"으로 | `rc_frame` 은 **입력 대기**였다 |

그리고 **내가 만든 결함 3건**도 측정으로 잡았다:
- 벽시계 예산이 판정을 머신 부하에 종속시킴
- `countJudged` 가 `ok` 필드를 안 세 판정하는 템플릿을 "판정 0개"로 고지(거울상)
- 조기 반환이 고지를 삼킴(3회 — 미검증 건수·성격·공간 고지)
