# 경쟁 서비스 대비 격차와 계획 (2026-08-01)

> 대조 대상 ①: **모션 조립체 데모** — 운동학을 갖춘 기계 조립체(기어·벨트·베벨·랙피니언·크랭크),
> 재생/일시정지 애니메이션, 역할 태그가 붙은 BOM, 감속비 표시, 로봇 자산(SO-101·LEAP·Crazyflie).
> 대조 대상 ②: **CAD 에이전트** — 5단계 파이프라인(이해→설계→생성→수정→검증)을 화면에 노출,
> 자동 재시도 3회·품질 검증 2회, 파라미터 실시간 편집, 생성 코드 표시, 치수 대조 결과.
>
> 관련: [`drawing-to-3d-methodology.md`](./drawing-to-3d-methodology.md) · [`fea-gap-vs-ansys-260801.md`](./fea-gap-vs-ansys-260801.md)

## 0. 한 줄 요약

**아키텍처는 이미 같거나 우리가 더 깊다. 지는 것은 「보여주기」다.**

②의 파이프라인(결정론 파싱 → LLM 계획 1회 → 결정론 생성 → 자동수정 → 치수 검증)은
**우리 방법론 §1.3「계획-실행 분리」와 사실상 동일**하다. 그런데 그들은 그 과정을 화면에 띄우고,
우리는 계산해 놓고 **응답에 싣지 않는다.**

① 도 마찬가지다. 4절 링크 속도·Grashof 판별·유성기어 관계식까지 계산하면서,
**그 결과로 움직이는 그림을 만들지 못한다.**

> 이 문서의 결론은 「기능을 더 만들자」가 아니라 **「이미 계산한 것을 내보내자」**다.

## 2. 진단 — 같은 결함이 반복된다

세 번 연속 같은 모양이다.

```
오늘 260731  missingFields/estimatedFields 를 만들고 → 라우트가 버려서 화면에 안 닿음
오늘 260801  개발자 가이드를 만들고 → 어디서도 링크 안 함
이 문서       repairRounds·stage·감속비·운동학 궤적을 계산하고 → 응답에 안 실음
```

**「있는 것이 안 닿음」**이 이 저장소의 지배적 결함이다. 기능이 부족한 게 아니라
**만든 것을 내보내지 않는다.** 경쟁 서비스가 더 나아 보이는 대부분은 이 차이다.

⚠ 그러므로 이 계획의 대부분은 **신규 개발이 아니라 배선**이다. 규모를 그렇게 잡는다.

## 3. 계획

### 3.1 1단계 — 배선 (이미 계산한 것을 내보낸다)

| # | 항목 | 무엇을 하나 | 규모 |
|---|---|---|---|
| W1 | **파이프라인 상태 노출** | 성공 응답에도 `stages[]`·`attempts`·`elapsedMs` 를 싣는다. 실패에만 있던 `stage` 를 전 구간으로 | **S** |
| W2 | **BOM 역할 태그** | 이미 있는 `service`/`role` 을 BOM 행에 실어 `DRIVE/DRIVEN/INPUT/OUTPUT/STRUCT/SUPPORT` 로 표기 | **S** |
| W3 | **감속비·메커니즘 제원** | `planetaryGear`·`gearGeometry` 결과를 조립 응답에 붙인다(감속비·잇수·모듈) | **S** |
| W4 | **치수 대조를 사용자 언어로** | `delta_pct` 를 「요청 80mm → 실제 79.8mm (0.25% 차이) ✓」 형태로 | **S** |

> ⚠ W1 은 **정직하게** 해야 한다. 시도 횟수를 보여 주는 것은 「2번 만에 됐다」는 자랑이 아니라
> **「1번에 안 됐다」는 고지**이기도 하다. 숨기지 않는 것이 목적이지 홍보가 아니다.

### 3.2 2단계 — 메커니즘 애니메이션 (M)

가장 큰 격차이자, 우리 강점을 **눈에 보이게** 만드는 항목.

```
fourBarPosition(θ) 를 θ = 0…360° 로 훑는다  →  각 프레임의 링크 자세
                                              →  motionTimelineEditor 트랙에 keyframe 으로
기어: 잇수비로 종동축 회전각 = 구동축 × (z1/z2)  →  회전 트랙
```

**밑바닥부터가 아니다** — 양쪽 끝(운동학·타임라인)이 이미 있고 가운데 변환만 없다.

착수 순서: `four_bar`(궤적이 비자명해 검증 가치가 크다) → `gear_train` → `conveyor`.

⚠ **검증 없이 애니메이션을 붙이지 않는다.** 「돌아간다」가 아니라 **「맞게 돈다」**를 확인한다:
- 4절 링크: 링 폐합 잔차 `loopResidual` 이 전 프레임에서 0에 수렴하는가
- 기어: 맞물림 점의 원주 속도가 두 기어에서 같은가
- Grashof 아닌 조합은 **회전하지 않아야** 한다(억지로 돌리면 그건 거짓말이다)

### 3.3 3단계 — 개별 판단

| 항목 | 판단 |
|---|---|
| **URDF 임포트**(SO-101·LEAP·Crazyflie 류) | **권하지 않음.** 「남의 모델을 보여 주는」 방향이라 우리 축(말로 만들어 제작까지)과 다르다. 요구가 확인되면 재검토 |
| 생성 코드 표시 강화 | `scad` 는 이미 나간다. **어떤 코드가 어떤 형상을 만들었는지** 잇는 UI 는 별도 판단 |

## 4. 하지 않는 것

- **경쟁 서비스의 데모 목록을 따라 만들지 않는다.** 키보드·드론 같은 항목은 데모 소재이지
  제조 고객의 요구가 아니다. 우리 54종은 **실제 발주가 나오는 것들**로 골라져 있다.
- **애니메이션을 위한 애니메이션.** 검증되지 않은 움직임은 그럴듯할수록 위험하다 —
  §3.2 의 검증 조건을 못 지키면 그 메커니즘은 애니메이션을 붙이지 않는다.

---

## 5. 우리가 이미 앞서 있는 것 — 잊지 말 것

격차만 적으면 방향을 잃는다. 대조 중 확인된 우위:

- **강도까지 계산한다.** 기어 치근 응력(`gearBending`) · 베어링 수명 · 축 설계 · 공차 누적 —
  경쟁 데모는 **움직임까지**이고 우리는 **견디는지까지**다.
- **판정의 정직성.** 추정을 추정이라 표시하고(`estimatedFields`, 오경보 0.5%),
  미측정을 통과로 세지 않으며, 해석 결과에 **등급**(스크리닝/엔지니어링/인증후보)을 붙인다.
- **제조용 B-rep STEP.** 메시가 아니라 해석적 곡면 — CNC·금형에 바로 쓴다.
- **분야 폭.** 기계 18 + 건축 10 + 인테리어 9 + 조경 8 + 교량 6 + 토목 3 = **54종**.

---

## 6. 착수 조건·재평가

- **1단계(W1~W4)는 조건 없이 착수해도 된다** — 신규 기능이 아니라 이미 만든 것의 배선이고,
  「있는 것이 안 닿음」이라는 확인된 결함의 수정이다.
- **2단계는 1단계 이후.** 파이프라인 상태조차 안 보이는데 애니메이션부터 붙이는 것은 순서가 아니다.
- 이 문서는 **경쟁 데모가 아니라 우리 사용자가 막혔을 때** 다시 본다.
  ⚠ 「경쟁사에 있다」는 사실만으로는 재평가 사유가 아니다.
