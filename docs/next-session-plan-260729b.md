## 2. 이번 실측이 새로 찾은 것

### ⚠ A. `girder_bridge` 가 판정 0개인데 「이상 없음」으로 나간다 (P0)

```
girder_bridge  판정노드 1 | 자기정합 1 | 실판정 0 | verdict ok=true unavail=0
   - 바닥판 폭 자기정합  kind=self-consistency  ok=true
```

`dead`·`live`·`ultimate`·`service`·`section` 을 다 산출하면서 **부재 강도 판정을 하나도
하지 않는다**(배근 `As_mm2` 미선언이라 `rc_beam` 이 못 돈다). 그런데 그 사실을 고지하지
않고, `verdict.unavailable` 도 비어 있다.

**근본 원인 두 가지가 겹쳤다:**

1. **`countJudged` 가 자기정합을 안전 판정으로 센다.** 바닥판 폭이 선언값과 맞다는 것은
   **형상 자기정합**이지 구조 안전이 아니다. 그런데 그것 하나로 `evidenceSufficient` 가
   충족돼 「판정 0개」 경보가 꺼졌다 — 앞 세션에 넣은 안전망이 **범주 오류로 뚫린 것**이다.
2. **부재 판정 불가를 고지하는 채널이 교량에 없다.** 건축에는 `memberUnavailable` 이
   있는데 교량에는 대응물이 없다.

→ `kind: 'self-consistency'` 는 안전 판정 분모에서 제외하고 별도로 센다.
→ 교량도 배근/단면 미선언 시 `needInputs` 로 되돌린다.

### ⚠ B. 렌더러가 `ok` 불리언을 판정으로 그리지 않는다 (P0)

`renderGenericCheckTree` 는 `typeof node.pass === 'boolean'` 만 판정 배지로 그린다.
그런데 **교량 검사는 전부 `ok` 를 쓴다**:

| 템플릿 | 실판정 | 문서에 배지로 나온 수 |
|---|---:|---:|
| arch_bridge | 3 (+자기정합 1) | 1 |
| truss_bridge | 3 (+자기정합 1) | 1 |
| suspension_bridge | 4 | 1 |
| cable_stayed_bridge | 2 | 1 |

타이 인장·리브 축압축·행어 장력·주케이블 장력 같은 **실제 판정이 문서에서 판정으로
보이지 않는다.** 값은 나가는데 합·불 표시가 없다. §6-G ⑤(판정이 소비자에 도달 안 함).

⚠ A 와 B 는 **서로 반대 방향으로 틀렸다.** 하나는 자기정합을 판정으로 과대 계상하고,
다른 하나는 진짜 판정을 표시에서 누락한다 — 상쇄되지 않고 각각 다른 거짓말을 한다.

### ⚠ C. 마크업 누출 잔존 1건 (P1)

`building/steel_canopy` 에서 `**풍 상향력이 지배**` 가 원문 그대로 새어 나온다.
`domainSafetyReportHtml` 의 `r.ok === false` 분기가 아직 `esc` 를 쓴다(escMd 미적용).
`escMd` 를 넣을 때 이 자리를 놓쳤다 — **한 곳만 고치면 나머지에서 샌다**는 걸 또 확인했다.

### 이 과정에서 새로 찾은 결함

1. **IFC 공식 인증 세트 18파일 임포트 0건** (P2-10 을 하려다 발견)

   형태를 몰랐다. 기존 IFC2X3 코퍼스(17,269부품)는 개별 점을 써서 **한 번도 드러나지
   않은 구멍**이다. → 0건 → **207건**. 상세는 `REAL_CAD_CORPUS_PRIORS.md` §4차 채굴.
2. **마스트 단면을 가정으로 덮고 있었다** — 부품 실단면 2500×800 인데 `mastW²` 사용

3. **좌굴 추가가 verdict 를 뒤집었다** — `every(c => c.ok)` 가 판정 불가(null)를 falsy 로
   읽어 **입력이 없다는 이유로 교량이 FAIL** 이 됐다. 「확인 못 함 ≠ 기준 미달」이
   verdict 계산에서 무너진 것이라 `bridgeVerdict()` 로 분리했다.
4. **개구를 선언할수록 관통 검사가 꺼졌다** — `slab_with_openings` 는 필드명이
   `length/depth/thickness` 라 `width/depth/height` 로 읽으면 AABB 가 null 이 된다.
   **고치라고 안내한 바로 그 행동이 검사를 끄는** 최악의 형태였다.
5. **`try/catch` 가 import 누락을 삼켰다** — 기계 전도 배선이 통째로 사라진 채
   「해당 없음」으로 보였다. 실패는 이유를 남기도록 고쳤다.
