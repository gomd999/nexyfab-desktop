# NexyFab 상업화 준비도 평가 및 실행 계획

> **최신 판정 우선:** 이 문서의 기존 native-worker 수치와 P0-2는 과거 외부 CAD 상호운용성 트랙 기록이다. 기본 상품의 현재 구현·판정은 `docs/CAD_INDEPENDENT_IMPLEMENTATION_AND_COMMERCIAL_REVIEW_260809.md`를 우선한다. SOLIDWORKS 등 7개 외부 CAD의 설치·라이선스는 기본 서비스 출시 조건이 아니다.

- 기준일: 2026-08-09
- 평가 대상: AI 3D 생성, 정밀 CAD 전환, 전문가 검토, 제조 연계가 포함된 NexyFab
- 연계 문서: `docs/ROBOT_AI_CAD_IMPLEMENTATION_STATUS_REVIEW_260809.md`
- 현재 결론: **유료 Closed Beta/Pilot은 조건부 가능, NexyFab 자체 CAD 상용화를 우선하며 외부 전용 CAD 호환은 선택적 Enterprise 범위로 분리**

> 2026-08-09 전략 수정: 상업화의 필수 전제에서 SOLIDWORKS·Inventor·CATIA·Creo·Revit 등 외부 CAD 설치를 제외한다. `NexyFab 자체 CAD + 중립 제조 형식`을 주력 제품으로 정의하며, 아래 문서의 네이티브 CAD 워커 항목은 기본 상품이 아닌 선택적 상호운용성 트랙으로 해석한다. 전체 수정 계획은 `docs/NEXYFAB_CAD_INDEPENDENT_COMMERCIALIZATION_PLAN_260809.md`를 기준으로 한다.

## 1. 상업화 가능 여부

### 1.1 가능한 상업화 형태

현재 바로 검토할 수 있는 형태는 다음과 같다.

1. 초대된 고객만 사용하는 유료 Closed Beta
2. AI 개념 설계 및 편집 가능한 3D 초안 생성 서비스
3. 전문가 검토가 포함된 설계 보조 서비스
4. 정밀 CAD 전환 전 사전 검토 및 요구사항 정리 서비스
5. 명확한 범위와 책임 조건을 둔 유료 PoC 또는 기업 Pilot

이 단계에서는 결과물을 다음과 같이 표시해야 한다.

- `AI 초안`
- `내부 검증 완료`
- `전문가 검토 대기`
- `NexyFab 정밀 CAD 검증 완료`
- `제조 검증 완료`

검증 단계가 끝나지 않은 결과에 `생산 가능`, `제조 보증`, `완전 정확`, `인증 완료` 같은 표현을 사용하면 안 된다.

### 1.2 현재 출시하면 안 되는 형태

- AI 결과를 사람의 검토 없이 생산 도면으로 판매
- 모든 복잡 제품과 모든 CAD 형식의 정확한 변환을 보장
- 네이티브 CAD 검증 없이 feature tree와 assembly semantics 보존을 보장
- 제조 전문가 확인 없이 DFM·공차·재료·공정 적합성을 보장
- 안전 관련 장비, 압력용기, 의료·항공·자동차 부품에 대한 자동 승인
- 고객 원본을 자동 덮어쓰거나 승인 없이 제조/RFQ로 전송

## 2. 현재 준비도 판정

| 영역 | 판정 | 근거 |
|---|---|---|
| AI 3D 및 정밀 CAD 흐름 | 강함 | AI 초안, 정밀 검증, 전문가 개입, r+1 개정 구조 구현 |
| 증거 추적성과 원본 보호 | 강함 | 해시 결속, 서명 검증, 원본 무변경, Closed Beta diff 0 |
| 자동화 품질 | 강함 | 35개 테스트 파일, 141개 테스트 통과, 프로덕션 빌드 통과 |
| UI 단계 안전성 | 양호 | 차단 사유와 단계 표시, 무단 적용·릴리스 경로 없음 |
| NexyFab 자체 정밀 CAD 증거 | 구현, 실제 target 증거 대기 | 통합 커널·독립 왕복·V2 감사 구현; 실제 제품 서명은 별도 필요 |
| 실제 제조 적합성 | 미충족 | 서명된 제조 검증 없음 |
| 운영 인프라 | 부분 충족 | 백업·모니터링 코드가 있으나 실제 복구·다중 서버 증거 부족 |
| 보안 운영 체계 | 부분 충족 | fail-closed 구조는 양호하나 독립 침투시험·운영 키 관리 증거 부족 |
| 법무·보험·책임 체계 | 확인 필요 | 약관은 있으나 CAD 오류·제조 손실 책임과 국가별 검토 필요 |
| 고객 성공·지원 체계 | 확인 필요 | SLA, 장애 대응, 전문가 배정, 분쟁 처리의 실제 운영 훈련 필요 |

### 종합 판정

- **유료 Closed Beta:** 조건부 Go
- **소수 기업 대상 유료 Pilot:** 조건부 Go
- **전문가 검토 포함 정밀 CAD 서비스:** NexyFab exact-CAD 증거와 전문가 체계 확보 후 Go
- **일반 공개 셀프서비스:** 현재 No-Go
- **생산 가능성 보증형 서비스:** 현재 No-Go
- **안전 필수 산업 적용:** 별도 인증·책임 체계 전에는 No-Go

## 3. 상업화 전에 반드시 해결할 P0 항목

### P0-1. 상품 정의와 책임 경계

다음 세 상품을 분리한다.

| 상품 | 제공 가치 | 결과물 책임 수준 |
|---|---|---|
| AI Concept | 빠른 3D 초안과 편집 구조 | 생산용 아님 |
| Verified Design | 내부 기하·운동·간섭 검증 포함 | 네이티브 CAD/제조 검토 전 단계 |
| Expert CAD | 네이티브 CAD 및 전문가 검토 포함 | 계약된 범위에서만 사용 가능 |

필수 조치:

- 화면, 다운로드 파일, 견적서, 계약서에 동일한 상태 용어 사용
- 검증되지 않은 결과에는 워터마크와 machine-readable 상태 포함
- 고객이 검증 단계를 건너뛰지 못하게 권한 정책 적용
- CAD 오류, 제조 손실, 간접손해, 고객 입력 오류의 책임 범위를 법률 전문가와 확정
- 안전 필수 사용처와 금지 사용처 명시

### P0-2. NexyFab 자체 exact-CAD 증거

- 통합 OCCT 커널 artifact, 버전, lockfile 및 policy hash 고정
- 상용 worker health와 no-stub/no-fallback mode 통과
- exact release target의 Part STEP 및 XCAF assembly 왕복 검증
- assembly tree, joint semantics, 단위, topology, drawing/PMI 및 STEP round-trip 검증
- 실패 사례를 숨기지 않고 형식·버전별 지원 매트릭스에 반영
- 지원하지 않는 형식은 업로드 전 또는 처리 전에 명시적으로 거부

통과 조건:

- 통합 상용 커널 준비 및 identity check 통과
- exact release target의 필수 check 100%
- 독립 importer 왕복 비교 통과
- 치명적 silent corruption 0건

### P0-3. 제조 검증과 전문가 운영

- 로봇 18개 구동계 occurrence에 대한 실제 제조 검증
- DFM, 공차 누적, BOM, 체결부, 케이블, 재료, 공정 계획 서명
- 분야별 검토자 자격·경력·이해상충 정책 수립
- 도메인 검토자와 독립 검토자의 분리
- 검토 시간, 반려, 재작업 및 에스컬레이션 절차 확정
- 전문가 판단과 시스템 검증 결과가 충돌할 때 우선순위 정의

통과 조건:

- 정확한 release target에 제조 서명 존재
- 서로 다른 두 검토자의 최종 서명 존재
- 검토자 키 폐기·교체·분실 대응 훈련 완료

### P0-4. 운영 보안

- 운영 환경에 중앙 Redis rate limit 적용
- 비밀키를 환경 문자열로 장기 보관하지 않고 KMS/HSM 또는 관리형 secret store로 이전
- 관리자, 전문가 및 워커 계정에 MFA와 최소 권한 적용
- 업로드 CAD를 악성 입력으로 간주한 격리 실행
- 워커의 네트워크 egress, 파일 접근 및 실행 시간 제한
- SBOM, 의존성 취약점, 컨테이너/호스트 취약점 점검
- 외부 침투시험 및 수정 후 재시험
- 감사 로그의 위변조 방지와 보존 기간 확정

통과 조건:

- Critical/High 미조치 취약점 0건
- 관리자 및 전문가 MFA 적용률 100%
- 권한 없는 타 고객 파일 접근 테스트 0건
- 서명·웹훅 replay 공격 차단 증거 확보

### P0-5. 백업·복구·장애 대응

- SQLite 개발 운영을 끝내고 상용 DB 구성 확정
- DB, 객체 저장소, 서명 메타데이터 및 감사 로그 백업
- 백업 생성이 아니라 실제 복구 훈련 수행
- RPO/RTO를 상품 약속과 연결
- 워커 장애, 결제 장애, 저장소 장애, AI 공급자 장애 runbook 작성
- 상태 페이지와 고객 통지 절차 준비

통과 조건:

- 격리된 환경에서 복구 훈련 성공
- 목표 RPO/RTO 충족 증거
- 장애 모의훈련과 담당자 호출 체계 확인

## 4. P1 상업 운영 준비

### 4.1 고객 데이터와 지식재산권

- 고객 CAD 소유권과 처리 권한을 업로드 전에 확인
- 고객 파일을 AI 학습에 쓰는지 여부를 명시하고 기본값을 `사용 안 함`으로 유지
- 테넌트별 보존·삭제 정책과 법적 보존 예외 정의
- 백업과 파생물까지 포함한 삭제 검증
- 참고 코퍼스의 파일별 출처, 라이선스, 평가 허용 범위 기록
- 제3자 CAD SDK, 폰트, 모델, 데이터 및 번역기의 상업 라이선스 검토
- 직원·외주 전문가의 비밀유지 및 결과물 권리 귀속 계약 체결

### 4.2 결제·환불·세금

- 실제 결제 sandbox에서 가입→결제→갱신→실패→취소→환불 전 과정 검증
- 웹훅 서명, 중복 이벤트, 순서 역전 및 재처리 검증
- 국가별 세금, 통화, 인보이스 정책 검토
- CAD 전문가 작업이 시작된 뒤의 환불 규칙 명확화
- 사용량 과금의 계측값과 고객 표시값 일치 검증

### 4.3 SLA와 지원

- 상품별 처리 시간과 지원 시간을 정의
- AI 작업, CAD 워커, 전문가 검토 시간을 분리해 표시
- 결과 반려와 재작업 횟수 정책 정의
- Sev-1~Sev-4 장애 분류와 응답 목표 정의
- 보안 사고, 데이터 손상, 결제 분쟁, 제조 불일치 담당자 지정

### 4.4 관측 가능성과 비용

- 요청별 trace ID를 AI 생성→CAD 작업→전문가 검토까지 연결
- 오류율, 처리시간, 큐 지연, 재시도, 워커별 성공률 모니터링
- 파일 크기·형식·복잡도별 원가 측정
- AI 토큰, CAD 라이선스, 워커 시간, 전문가 시간, 저장소 비용을 주문별 원가로 집계
- 낮은 마진 또는 반복 실패 작업을 자동 중단하거나 수동 견적으로 전환

## 5. P2 공개 출시 준비

- 접근성, 모바일 보조 흐름 및 다국어 핵심 약관 검수
- 고객 온보딩과 샘플 프로젝트
- 지원 형식·제한·정확도 범위를 공개 문서화
- API 버전 정책, deprecation 기간 및 SDK 계약 테스트
- 고객별 사용량 제한과 비용 폭주 방지
- 데이터 이전, 계정 탈퇴, 프로젝트 내보내기 검증
- 취약점 신고 정책과 보안 연락처
- 공급자 장애와 가격 변경에 대한 대체 전략
- 고객이 결과의 provenance와 검증 상태를 확인할 수 있는 검증 페이지

## 6. 권장 출시 단계

### 단계 A — 내부 상업화 준비

목표 기간: 2~4주(외부 라이선스와 담당자 확보 기간 제외)

- 상품·책임 상태 모델 확정
- 운영 환경 분리 및 중앙 rate limit
- secret manager, MFA, RBAC 적용
- 결제·백업·복구·웹훅 E2E 검증
- 운영 대시보드와 장애 runbook 작성

종료 게이트:

- P0 운영 항목 통과
- 독립 보안 점검의 Critical/High 0건
- 복구 훈련 성공

### 단계 B — Design Partner Pilot

목표: 3~5개 기업, 프로젝트 수와 형식을 제한

- 저위험 제품군만 허용
- 프로젝트마다 지정 전문가 배정
- 모든 출력의 상태와 제한을 고객에게 명시
- 정확도, 수정 횟수, 처리시간, 고객 만족도 및 실제 원가 수집
- 제조 전에는 별도 최종 승인 요구

종료 게이트:

- 치명적 데이터 유실·교차 테넌트 노출 0건
- silent CAD corruption 0건
- 전문가 검토 누락 0건
- 고객 프로젝트별 원가와 마진 측정 가능
- 고객이 결과 제한을 이해했다는 확인 기록 100%

### 단계 C — 제한적 유료 Beta

목표: 지원 형식과 산업을 제한한 초대형 유료 서비스

- 네이티브 CAD 지원 매트릭스 공개
- SLA와 환불 기준 적용
- 주간 안전·품질 검토
- 실패 형식과 모델을 자동 차단 목록에 반영
- 30일 이상 안정성 지표 수집

종료 게이트:

- 목표 가용성 달성
- 복구·사고 대응 훈련 재통과
- 결제와 환불 실거래 검증
- 고객별 데이터 삭제 검증
- 외부 전문가·제조 증거 프로세스 반복 성공

### 단계 D — 일반 공개

다음 조건을 모두 충족한 뒤 결정한다.

- 지원 형식별 충분한 실제 고객 검증 표본
- 보안 재시험 통과
- 법무·보험·세무 검토 완료
- 전문가 공급 용량과 대체 인력 확보
- 단위경제성 검증
- 장애와 분쟁을 처리할 운영 인력 확보
- 생산 보증 상품은 별도 계약과 별도 승인 체계를 적용

## 7. 출시 판단 지표

| 분류 | 핵심 지표 | 초기 목표 |
|---|---|---:|
| 정확도 | 검증 후 발견된 치명적 CAD 손상 | 0건 |
| 안전 | 검토 없이 생산 단계로 이동한 건 | 0건 |
| 데이터 | 교차 테넌트 접근 및 원본 훼손 | 0건 |
| 네이티브 CAD | 지원 대상 job 승인율 | 100% |
| 제조 | 필요한 제조 서명 누락 | 0건 |
| 운영 | 백업 복구 성공률 | 100% |
| 보안 | 미조치 Critical/High | 0건 |
| 결제 | 중복 청구 및 잘못된 권한 부여 | 0건 |
| 고객 | 첫 유효 결과까지 걸린 시간 | 상품별 목표 설정 |
| 경제성 | 프로젝트별 공헌이익 | 양수 |

목표 가용성, 처리시간, 수정 횟수 및 정확도 허용치는 첫 Design Partner Pilot의 실제 분포를 측정한 뒤 확정한다. 근거 없이 높은 SLA를 먼저 약속하지 않는다.

## 8. 표준 및 거버넌스 기준

상업화 준비 과정은 다음 기준에 맞춰 증거를 축적한다.

- NIST AI RMF의 `Govern → Map → Measure → Manage`
- NIST Generative AI Profile의 콘텐츠 출처, 사전 배포 시험 및 사고 공개 관점
- OWASP ASVS 기반 웹 애플리케이션 보안 검증
- ISO/IEC 27001:2022 기반 정보보안 관리체계
- 판매 국가별 개인정보·전자상거래·AI·제조물 책임 규정

인증 취득 자체보다 통제의 실제 작동 증거를 먼저 만든다. 인증 여부와 법적 적용 범위는 판매 국가, 고객 산업 및 계약 구조가 확정된 뒤 전문 자문으로 결정한다.

## 9. 실행 우선순위

1. 상품 범위와 금지 주장을 확정한다.
2. 7개 네이티브 CAD 워커 및 라이선스를 확보한다.
3. 108개 실제 job과 로봇 r+1 대상 네이티브 검증을 끝낸다.
4. 제조 전문가와 최종 독립 검토자 운영 체계를 계약한다.
5. Redis, secret manager, MFA, 격리 워커를 운영 환경에 적용한다.
6. 백업 복구, 결제, 웹훅 및 장애 대응 E2E를 검증한다.
7. 독립 침투시험과 법무·라이선스 검토를 완료한다.
8. 3~5개 Design Partner Pilot을 수행한다.
9. 품질·원가·지원 지표를 기반으로 제한적 유료 Beta 여부를 결정한다.
10. 반복 가능한 외부 증거와 운영 지표가 확보된 뒤 일반 공개를 검토한다.

## 10. 최종 권고

현재 제품은 단순 데모 단계를 넘었고 **통제된 유료 Pilot을 준비할 가치가 있는 수준**이다. 핵심 기술 구조를 다시 만드는 것보다 실제 네이티브 CAD, 제조 전문가, 운영 보안 및 고객 프로젝트 증거를 확보하는 것이 우선이다.

권장 전략은 다음과 같다.

> `AI 자동 생산 CAD`로 공개 출시하지 않고, `AI 설계 가속 + 검증 상태 공개 + 필요 시 전문가 정밀 CAD` 상품으로 제한된 기업 Pilot부터 시작한다.

Pilot에서 정확도, 시간, 원가와 책임 경계가 반복 검증되면 제한적 유료 Beta로 확대한다. 실제 생산 보증은 일반 SaaS 기능이 아니라 별도 전문가 서비스와 계약·보험·승인 절차가 결합된 상품으로 운영하는 편이 안전하다.
