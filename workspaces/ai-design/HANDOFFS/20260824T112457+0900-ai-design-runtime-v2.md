# AI Design Runtime V2 handoff

- Producer scope: `scope/ai-design`
- Consumer scopes: `scope/precision-cad`, `integration/nexyfab`
- Date: 2026-08-24 KST
- Status: AI Design implementation complete; Precision CAD and integration-owned persistence remain consumer work

## Outcome

AI Design now has a server-authoritative command path. A browser can request an action, but it cannot save a completed runtime snapshot, submit validation `PASS`, choose a provider deployment ID, publish generated artifacts, or author a Precision CAD receipt.

The implementation is concept-design only. It does not create an exact CAD kernel, manufacturing release decision, or inherited verification claim.

## Runtime and API contract

### Bootstrap

`POST /api/nexyfab/ai-design/workspace-session`

```json
{
  "operation": "create",
  "projectId": "project-1",
  "sessionId": "session-1",
  "revisionToken": "rev-0",
  "inputs": []
}
```

The server constructs and validates the initial runtime. Legacy `save` and client-authored `state` bodies are rejected. GET remains project/session scoped.

### Commands

`POST /api/nexyfab/ai-design/workspace-session/actions`

Every command uses `nexyfab.ai-design-workspace-command.v2`, a unique `commandId`, project/session binding, expected runtime revision, issued timestamp, a strict command type, and a bounded payload.

Client command types:

- `REQUEST_UNDERSTANDING_CONFIRMATION`
- `INGEST_INPUTS`
- `START_GENERATION_REQUEST`
- `RUN_GENERATION_STAGE_REQUEST`
- `RETRY_GENERATION_REQUEST`
- `SELECT_CANDIDATE`
- `BEGIN_PARAMETRIC_EDIT`
- `ADJUST_GAUGE`
- `REQUEST_PRECISION`
- `CANCEL`
- `RESUME`

`RUN_GENERATION_STAGE_REQUEST` invokes one server stage. The UI may continue with the returned revision until all four stages complete. The final candidate-validation stage automatically stores immutable candidate manifests and publishes two or three sufficiently distinct concept candidates. The browser never supplies the stage result.

## Trust boundary

- Authenticated plan data overrides every model entitlement input.
- Public model IDs resolve to server-private provider/runtime model IDs only inside the worker.
- Provider fallback cannot silently use another vendor deployment for a selected stage; a failed stage enters governed retry/fallback state.
- Provider output is closed-schema parsed, identity-bound, checked for forbidden authority/release claims, content-digested, and stored before the stage can pass.
- HMAC evidence receipts bind project, session, command, checkpoint, runtime/generation revisions, stage, input/output digests, outcome, issuer, and expiry.
- Candidate artifacts are append-only, ownership-bound, digest-bound, and use `supersedes` lineage instead of overwrite.
- Candidate diversity is a concept-quality gate only. Critic and exact verification remain `NOT_RUN`.
- Unresolved input conflicts enter `NEEDS_INPUT`; all alternatives remain visible and no value is selected automatically.
- Copyright/provenance policy remains fail closed. Only concepts and independently worded method-level reasoning are generated; source rights and derivative-use permission are required before worker execution.

Required secret for server evidence:

```text
GENERATION_EVIDENCE_SIGNING_SECRET=<at least 32 bytes>
```

## Precision CAD UI consumption contract

Precision CAD should consume `createAiDesignWorkspaceV2ViewModel(...)`, not mutate AI runtime state directly.

The V2 view-model provides:

- desktop/mobile primary region selection;
- mobile intent/generation/candidate/gauge/precision/recovery bottom-sheet selection;
- a sticky mobile primary action and 44 px gauge touch targets;
- public model selection/change explanations without private deployment IDs;
- ranked conflict/missing/assumption questions;
- real stage counts with `percent: null` rather than invented progress;
- two/three-candidate diversity status;
- fine/coarse gauge controls and confirmation flags;
- separate concept, candidate-evidence, Precision verification, and manufacturing-release states.

On `REQUEST_PRECISION`, Precision CAD owns all exact geometry execution and verification. It must return its versioned receipt through the existing Precision handoff boundary. AI candidate evidence marked `unknown`, `not_run`, or `invalidated` must never be upgraded by the UI.

No file under `worktrees/precision-cad` was modified in this implementation.

## Integration-owned follow-up

Commercial mode intentionally fails closed with `AI_DESIGN_WORKSPACE_POSTGRES_AUTHORITATIVE_REQUIRED`. Integration must provide:

- PostgreSQL CAS workspace repository with tenant/project/session ownership;
- durable stage, evidence-receipt, candidate-manifest, and command-idempotency tables/object storage;
- a leased background job adapter if stages should continue without user-issued stage requests;
- retention, deletion, observability sink, and failure-recovery policy;
- E2E wiring from the actual Precision CAD React/Three.js consumer to these APIs.

The in-memory artifact repository is a non-commercial reference implementation, not release evidence.
