# AI Design to Precision CAD binding memorandum

- Status: `DOCUMENTED_NOT_IMPLEMENTED`
- Owner: `scope/precision-cad`
- Date: `2026-08-24`
- Release effect: none; this document is not runtime evidence and cannot change a
  `HOLD`, `NOT_RUN`, or `PREVIEW` state to `PASS`.

Companion product plan:
`workspaces/precision-cad/MULTI_DOMAIN_PRODUCT_PLAN.md`.

## Decision

Precision CAD work may proceed without editing the AI Design worktree or an
integration-owned shared path. Cross-scope bindings are recorded here as
requirements. Until an integration commit supplies a versioned shared contract,
all AI-originated input is untrusted candidate data and never authoritative CAD.

Implementation changes made from `scope/precision-cad` must remain inside paths
owned by the Precision CAD scope in `workspaces/registry.json`. In particular:

- do not edit `src/lib/ai/**`, AI routes, providers, prompts, retrieval, or model
  orchestration;
- do not add a new direct import from an AI-owned path;
- do not edit `packages/**`, root configuration, CI, or other shared paths;
- record every required AI, platform, or integration change in Markdown;
- preserve the current release `HOLD` until real, current evidence passes all
  Precision CAD gates.

## Trust boundary

| Input | Precision CAD treatment | May create exact CAD? | May become release evidence? |
| --- | --- | --- | --- |
| User-entered dimensions and constraints | Untrusted requirements candidate | Only after strict validation and deterministic compilation | Only after exact-kernel verification |
| Approved, independently written concept card | Non-authoritative design rationale | Only through structured intent | No; the resulting exact artifact needs separate evidence |
| AI Design intent envelope | Untrusted candidate | Only after schema, rights, ambiguity, and feasibility gates | No direct authority |
| Raw AI-generated SCAD/JSCAD/source code | Preview-only executable text | No authoritative path | Never |
| Manual or encyclopedia original text, tables, figures, screenshots, or sample code | Forbidden input | No | Never |
| Reference data with missing or unclear commercial/derivative rights | `RIGHTS_HOLD` | No | Never |
| Exact B-rep generated by the bound OCCT kernel | Precision CAD artifact candidate | Yes | Only after all required checks and receipts pass |

AI must never assert exactness, kernel verification, manufacturing readiness, or
release eligibility on behalf of Precision CAD. Only Precision CAD may create
those states from its own current artifacts and kernel identity.

## Concept-only copyright rule

The manuals and the engineering encyclopedia may inform ideas, principles,
formula relationships, workflow requirements, and terminology only. They must
not be copied into this worktree or supplied to a runtime prompt, retrieval
index, embedding store, few-shot example, fixture, or generated source template.

An admissible concept card must be written independently and contain only the
minimum engineering concept needed by the implementation. It must not preserve
the source's sentences, table arrangement, figure composition, example sequence,
distinctive selection/ordering, screenshots, or CAD/source code. Formulae and
facts must be restated with independently selected symbols, structure, and test
examples. A citation or a wording change alone is not a rights approval.

Every concept card intended for implementation must carry, at minimum:

```text
conceptId
conceptVersion
independentStatement
variablesAndUnits
constraintsAndAssumptions
independentExample
sourceClass
sourceReference
sourceContentHash
rightsBasis
allowedUses
reviewStatus: APPROVED | HOLD | REJECTED
reviewer
reviewedAt
conceptContentHash
```

Missing, unverifiable, stale, or conflicting rights data is `HOLD`. Precision
CAD may validate the binding and state, but it must not invent or self-approve a
license decision.

independently verifiable; an AI-supplied `APPROVED` string is not sufficient.

## Precision-owned implementation sequence

All implementation below stays in Precision CAD-owned paths. Shared graduation
is deferred to integration.

## Current implementation facts

The local plan is based on the shipping paths, not on a hypothetical greenfield
pipeline:

- `src/lib/occt/featurePlan.ts` already translates a validated `FeatureTree` to
  deterministic OCCT commands for extrude, revolve, boolean, fillet, chamfer,
  hole, and open-face shell operations.
- `src/lib/occt/planExecutor.ts` already executes that command plan through an
  injected OCCT bridge and retains the final exact shape.
- sweep, loft, pattern, rib, and sweep-path nodes are currently reported as
  unsupported by the exact plan. The first binding must reject them instead of
  silently switching to SCAD or a mesh.
- `containers/occt-exact/src/executor.ts` currently accepts STEP artifacts for
  `EXACT_BREP_BUILD` and normalizes/verifies them. It does not build geometry
  directly from an AI intent or feature program.
- `src/app/api/cad/v1/feature-program/route.ts` and
  `src/app/api/cad/v1/part-step/route.ts` are compatibility aliases to legacy
  handlers. The STEP handler still imports validation and manufacturing helpers
  from `src/lib/ai/**`; it is not the future cross-scope boundary.
- `src/lib/cad/workspaceRevisionStore.ts` already requires exact B-rep hashes,
  artifact-graph consistency, provenance, real-kernel identity, and content-hash
  integrity before persistence.
- `capabilities/precision-cad/single-part-candidate/**` already validates source
  evidence and dependency readiness but does not yet consume an AI intent.

The required flow is therefore:

```text
AI Design envelope (later)
  -> Precision candidate intake
  -> allow-listed FeatureTree
  -> OcctPlan
  -> exact OCCT execution
  -> STEP + shape identity + verification receipt
  -> cad-workspace-envelope persistence
```

Raw AI code, OpenSCAD preview geometry, and mesh fallback do not enter this
authoritative flow.

## Milestones and gates

### M0: scope and baseline lock

Deliverables:

- keep this memorandum as the governing boundary;
- capture the current Precision commit and dirty-path inventory before coding;
- freeze the first exact operation set to `extrude`, `revolve`, `boolean`,
  `hole`, `fillet`, `chamfer`, and open-face `shell`;
- classify `sweep`, `loft`, `pattern`, `rib`, `sweep_path`, raw code, and mesh
  fallback as blockers.

Gate: documentation and fixtures make no shared-compatibility or release claim.

### M1: consumer-draft contract

The capability-local contract uses a clearly local schema such as
`nexyfab.precision-cad.ai-intent-consumer-draft.v1`. It must not reuse the final
`nexyfab.ai-design-intent.v1` name before integration owns that schema.

Validation order:

1. bounded byte size and nesting depth;
2. exact root and nested keys;
3. safe identifiers, unique IDs, finite values, units, and coordinate frame;
4. parameter/constraint/tolerance relationships;
5. allow-listed feature operation and dependency graph;
6. ambiguity resolution state;
7. concept-card content hashes;
8. independent rights-receipt ID, SHA-256, approval state, and freshness;
9. prompt/model/output provenance fields;
10. canonical intent content hash.

Gate: invalid inputs produce stable blockers; valid input returns
`CANDIDATE_ACCEPTED`, never `VERIFIED` or `RELEASE_READY`.

### M2: deterministic FeatureTree mapping

Mapping rules:

- preserve stable feature IDs from the accepted envelope;
- normalize all geometry to millimetres once, recording the source unit;
- require an explicit coordinate frame; do not infer axes from prose;
- make every boolean/hole/edge operation reference an already declared host;
- validate positive dimensions and operation-specific feasibility bounds;
- require explicit topological selectors for fillet/chamfer when exact identity
  cannot be derived from stable generative names;
- fail the entire authoritative mapping when one required operation is
  unsupported; no partial-success exact claim.

Gate: canonical intent hash deterministically maps to one canonical FeatureTree
hash, and permutation/duplicate/substitution tests fail closed.

### M3: local exact compiler qualification

The first compiler is a Precision-owned qualification path using
`featureTreeToOcctPlan`, `executeOcctPlan`, the node OCCT bridge, detailed shape
inspection, and STEP export/re-import. It is not yet a production job route.

Required output bindings:

```text
intentSha256
rightsReceiptSha256
featureTreeSha256
occtPlanSha256
kernelBuildSha256
kernelWasmOrImageSha256
stepArtifactSha256
shapeIdentitySha256
inspectionSha256
roundtripSha256
```

Gate: unsupported nodes, embedded stale child snapshots, missing final shape,
invalid/non-solid B-rep, non-empty warnings requiring review, STEP mismatch, or
any hash substitution returns `HOLD`.

### M4: workspace and lineage binding

Use the existing `nexyfab.cad-workspace-envelope.v1` validation rather than
introducing a second authoritative workspace format. Store the AI intent and
rights receipt as non-authoritative provenance sources; store the exact geometry
and kernel identity as Precision authority.

The binding helper must ensure:

- project/revision/semantic/artifact graph agreement;
- exact geometry hash equals the model artifact hash;
- the qualification receipt names the same intent, rights, kernel, STEP, and
  shape hashes;
- changing any upstream hash requires a new workspace revision;
- downstream manufacturing lineage is invalidated on revision change.

Gate: the existing workspace validator passes without weakening any current
check, and tampering tests fail at every binding edge.

### M5: internal intake, still inactive

Add an authenticated and bounded internal route only after M1-M4 are pure and
tested. Before shared integration it accepts local fixtures for qualification
and reports `productionActivation: NOT_RUN`. It must not call an AI provider,
accept a raw manual, execute generated code, or expose a public release path.

Gate: missing auth is denied, stale/replayed artifacts are denied, and the route
cannot return a release-ready result.

### M6: integration-owned production job graduation

This milestone is intentionally not implemented on `scope/precision-cad`.
Integration must:

- graduate one reviewed shared intent package;
- add an immutable intent-artifact job kind rather than overloading the current
  STEP-only `EXACT_BREP_BUILD` semantics;
- bind the AI envelope artifact through the existing job authorization and
  receipt contracts;
- run exact construction inside the isolated `occt-exact` service;
- compare the shared package against the local consumer draft and delete the
  duplicate draft after parity is proven.

Gate: the isolated worker, job orchestrator, artifact store, rights verifier,
and Precision workspace all bind the same source revision and hashes.

### M7: AI Design cutover

After M6, `worktrees/ai-design` may emit the shared envelope. The cutover must be
tested with frozen cross-worktree fixtures:

1. AI produces intent and provenance only;
2. Precision rejects raw SCAD/code and unapproved rights data;
3. Precision deterministically creates and verifies exact geometry;
4. AI cannot mutate the exact artifact or any release state;
5. changing the model, prompt, concept card, rights receipt, intent, or kernel
   creates a new hash lineage and invalidates prior downstream evidence.

Gate: cross-scope parity, negative substitution cases, and end-to-end artifact
lineage pass on `integration/nexyfab`; commercial release remains separately
subject to existing external evidence gates.

### PC-A: candidate intake

- Add a capability-local draft under
  `capabilities/precision-cad/ai-intent-candidate/**`.
- Add a strict legacy adapter under `src/lib/cad/**` only if an existing CAD
  caller needs compatibility.
- Parse into a candidate value without executing source code or creating B-rep.
- Return stable blockers such as `RIGHTS_EVIDENCE_UNBOUND`,
  `AMBIGUITY_UNRESOLVED`, `UNITS_INVALID`, `CONSTRAINT_INVALID`, and
  `UNSUPPORTED_OPERATION`.

Definition of done: malformed, rights-unbound, raw-code, and unknown-operation
inputs fail closed; valid fixtures remain `CANDIDATE`, never `PASS`.

### PC-B: deterministic exact compilation

- Map only allow-listed intent operations to existing Precision CAD feature
  builders.
- Require explicit units, coordinate frame, dimensions, tolerances, and feature
  references.
- Bind the result to the real OCCT build and WASM/image hashes.
- Generate new Precision CAD geometry; do not treat AI SCAD or a mesh preview as
  authoritative geometry.

Definition of done: identical envelope and kernel identity produce identical
canonical geometry/artifact hashes, or a stable blocker is returned.

### PC-C: verification and persistence

- Verify B-rep validity, topology expectations, dimensional constraints,
  regeneration, edit stability, and required STEP export/re-import behavior.
- Persist only a `nexyfab.cad-workspace-envelope.v1` whose requirements,
  semantic document, exact geometry, relations, artifact graph, provenance, and
  kernel identity hashes agree.
- Record the AI intent and rights receipt as provenance inputs without granting
  them exact-geometry authority.

Definition of done: a changed intent, rights receipt, kernel, geometry, or
topology hash invalidates the candidate and any downstream manufacturing
lineage.

### PC-D: release qualification

- Keep preview, candidate, verified, and release states distinct.
- Require zero false verification and zero destructive part merges.
- Require current, independently reviewed feature-axis, STEP, blind-challenge,
  and manufactured-pilot evidence where the existing release gates demand it.
- Never synthesize, backdate, or timestamp-refresh missing external evidence.

Definition of done: `mechanical:contracts:check`, `mechanical:scope:check`, the
Precision workspace check, and bounded owned-root verification all pass against
the same source revision and artifact set.

These entries are integration requests only. They do not authorize edits outside
the Precision CAD scope branch.

## Required local tests

- exact schema and unknown-key rejection;
- byte, depth, collection, identifier, and finite-number bounds;
- unit and coordinate-frame normalization without silent guessing;
- concept-card and rights-receipt hash substitution rejection;
- raw SCAD/JSCAD/source rejection on the authoritative path;
- unsupported operation and unresolved ambiguity rejection;
- deterministic regeneration and geometry-hash parity;
- topology expectation and persistent-reference survival;
- exact-kernel identity and stub-fallback rejection;
- STEP export/re-import and saved-workspace integrity;
- stale revision, changed input, changed kernel, and changed artifact invalidation;
- proof that AI fields cannot set verified or release-ready state.

## Non-goals

- implementing or changing an AI provider, prompt, RAG index, model router, or
  freeform SCAD generator;
- copying or transforming manual/encyclopedia expression inside this worktree;
- defining a competing shared contract from a scope branch;
- treating a Markdown checklist, unit test, preview mesh, or self-reported
  aggregate as commercial release evidence;
- weakening an existing fail-closed gate to make a candidate pass.

## Handoff rule

At handoff, report Precision-owned implementation and verification separately
from the deferred bindings above. Uncompleted cross-scope items stay visible as
blockers and must not be reworded as completed work. Any shared-package or
registry change requires an explicit integration decision on
`integration/nexyfab`.
